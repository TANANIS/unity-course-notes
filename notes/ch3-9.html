ch3_9 RigidbodyAnComponent_1（物理元件介紹）

這堂把前面的 FixedUpdate()、Vector3 與 Unity 的 Component 系統接到物理操作上。核心是認識 Rigidbody，並知道如何取得元件、指定施力方向，以及為什麼物理更新通常放在固定時間步中。

RIGIDBODY · FIXEDUPDATE · GETCOMPONENT

GameObject 是容器，Rigidbody 是讓物件參與物理模擬的 Component

這堂開始不只是直接改 Transform，而是讓 Unity 的物理系統參與物件運動。先取得 Rigidbody，再透過方向向量表示要往哪裡施力。

01Rigidbody物理元件與剛體概念 02FixedUpdate固定時間步處理物理 03GetComponent取得物件身上的元件 04GetComponentInChildren往子階層取得元件 05方向與力量Vector3.up / right
01

Rigidbody：讓固體 GameObject 參與 Unity 物理模擬

課程先用「剛體」建立直覺：理想剛體可以視為不會因受力而改變形狀的固體。Unity 裡的 Rigidbody 則是常用的物理 Component，讓 GameObject 能進入物理系統，之後才能用物理方式推動它。

GameObject
├── Transform
├── Collider
└── Rigidbody  ← 物理元件

這裡要先把「物件」與「元件」分開理解。GameObject 本身比較像容器，真正提供移動、碰撞、渲染或物理能力的是掛在它身上的 Component。

一句話記憶Rigidbody 是掛在 GameObject 上的物理元件，不是另一個 GameObject。
02

物理操作通常放在 FixedUpdate()

老師把前一堂的時間概念接回來：FixedUpdate() 依固定時間步執行，因此 Rigidbody 的持續物理運算通常放在這裡，而不是直接跟著不固定的畫面 FPS 跑。

void FixedUpdate()
{
    // 持續性的 Rigidbody 物理操作通常放在這裡
}

這跟前一堂形成很清楚的對照：

Update()
→ 跟畫面 Frame 走
→ 每次間隔可能不同

FixedUpdate()
→ 跟固定物理時間步走
→ 適合持續性的物理運算
概念校正

不要背成「只要碰到 Rigidbody，所有程式都必須塞進 FixedUpdate」。課程這裡真正要建立的是：持續施力、速度等物理操作通常交給固定物理時間步；輸入讀取等其他邏輯仍可能放在 Update()。

FixedUpdate畫面更新與物理更新是兩套不同節奏，不要把兩者混成同一件事。
03

GetComponent<T>()：取得目前 GameObject 身上的指定元件

接著課程進入「取得 Component」。一個 GameObject 身上可能同時有 Transform、Collider、Rigidbody 或其他腳本；程式取得指定元件後，就能進一步控制它。

Rigidbody rb = GetComponent<Rigidbody>();

這行可以拆成：

GetComponent<Rigidbody>()
→ 到目前這個 GameObject 身上
→ 找 Rigidbody Component
→ 把取得的參考交給 rb

因此這裡不是「取得整個物件」，而是從物件這個容器裡拿到某個具體功能元件。

核心模型GetComponent 取得的是 Component 參考；取得後才能呼叫該元件提供的功能。
04

GetComponentInChildren<T>()：往自己與子物件階層尋找元件

除了 GetComponent()，老師也先介紹 GetComponentInChildren()。當需要的 Component 不一定直接掛在目前 GameObject，而可能存在子物件時，就可以往子階層尋找。

Player
├── Rigidbody
└── Gun
    └── Muzzle
        └── SomeComponent
SomeComponent target =
    GetComponentInChildren<SomeComponent>();
差異GetComponent 先看自己；GetComponentInChildren 用於自己與子階層中的指定元件。
05

Vector3 表示方向，乘上的數值表示力量大小

老師最後把前面學過的向量接到物理概念。若希望物體往上，就用向上的方向；往右則使用向右的方向。方向向量再乘上一個數值，就能把力量放大。

Vector3.up
= (0, 1, 0)

Vector3.up * 10
= (0, 10, 0)

Vector3.right
= (1, 0, 0)

因此可以先用下面的心智模型理解：

方向 × 力量大小

Vector3.up * 10f
→ 往上、大小 10

Vector3.right * 100f
→ 往右、大小 100

下一個案例會把這些概念合起來：用鍵盤控制砲台移動，按下滑鼠左鍵時讓球被發射出去。

先不要過度簡化

課程目前是在建立「向量代表施力方向與大小」的直覺。實際 Rigidbody 最終怎麼移動，還會受到質量、重力、阻力與施力模式等物理設定影響；這些不是本堂字幕的重點，後面遇到再拆。

這堂核心取得 Rigidbody → 在固定物理時間步中操作 → 用 Vector3 決定施力方向。
