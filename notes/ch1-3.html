ch1_3 Unity3D 建立物件與父子關係

分清楚 Hierarchy 與 Project 各自在建立什麼，再掌握 Primitive、Duplicate，以及 Parent／Child 對 Transform 的影響。

GAMEOBJECT / ASSET / TRANSFORM

右鍵選單長得很像，不代表建立的是同一種東西

Hierarchy 管的是目前 Scene 裡的 GameObject；Project 管的是專案檔案與 Asset。Unity 很慷慨地讓兩邊都能右鍵 Create，也很節省地沒有替初學者承擔混淆成本。

01

從哪裡建立？先看你要的是 GameObject 還是 Asset

GameObject 選單
從上方選單選擇 GameObject → 3D Object，在目前 Scene 中建立新的場景物件。
Hierarchy 右鍵
在 Hierarchy 空白處按右鍵，可建立 Scene 裡的 GameObject；建立後會直接出現在 Hierarchy。
Project 右鍵
在 Project 的指定資料夾按右鍵並選擇 Create，建立的是 Material、Script、Folder 等 Asset 或專案檔案，不是直接出現在 Scene 裡的 GameObject。
Asset 放進 Scene
模型或 Prefab 等 Asset 可以從 Project 拖到 Scene／Hierarchy，Unity 才會在場景中建立對應的 GameObject 實例。
觀念校正

不是「在哪裡右鍵都能建立任何需要的東西」。Hierarchy 建立或整理場景物件；Project 建立與管理專案資產。兩者都叫 Create，只是 Unity 對命名重複有某種難以割捨的感情。

02

基本幾何體 Primitive

Cube 方體
六面立方體。最常拿來快速搭牆、地板、平台、障礙物與碰撞區，是灰盒原型的主力。
Sphere 球體
球形物件。適合球、行星、範圍提示或測試滾動物理。預設碰撞器為 Sphere Collider。
Capsule 膠囊體
中間是圓柱、上下為半球。形狀接近站立角色，常用來暫代玩家或敵人，也適合作為角色碰撞體。
Cylinder 圓柱體
上下平面、側面為圓弧。適合柱子、桶子、輪軸與圓形平台。碰撞形狀與效能仍要依實際用途檢查，不能因為外觀看起來合理就宣布物理系統已經畢業。
Plane 平面
由多個網格面組成的大型水平面，預設尺寸約為 10×10 Unity 單位。常作為測試地面，也方便之後做網格細分或頂點變形。
Quad 四邊面
只有一個矩形面，預設面向本地 Z 軸。適合 3D 場景中的圖片、告示牌、特效面片與簡單背景。
Plane 不等於 Quad

Plane 是水平、較大且有多個網格分段的地面；Quad 是單一四邊形面片。兩者看起來都扁，不代表用途相同，紙和磁磚也都扁，文明仍勉強把它們分開。

03

建立後通常會有哪些 Component？

Transform
位置、旋轉、縮放與父子階層。所有 GameObject 都一定有。
Mesh Filter
指定物件使用哪個 Mesh，也就是實際的幾何形狀資料。
Mesh Renderer
負責把 Mesh 畫到畫面上，並使用指定的 Material。
Collider
提供碰撞形狀。Cube、Sphere、Capsule 等會依形狀附上相應的 Collider。
一句話記憶Mesh Filter 決定長什麼形狀，Mesh Renderer 決定怎麼被畫出來，Collider 決定怎麼碰撞。
04

其他 3D Object 項目

Text - TextMeshPro
在 3D 世界中建立 TextMeshPro 文字。文字存在場景座標裡，不是一般 Canvas UI；適合角色頭頂名稱、世界內標示與立體字幕。
Legacy
舊版 3D Text 等相容功能。新專案通常優先使用 TextMeshPro，除非正在維護舊內容。
Ragdoll...
開啟 Ragdoll Wizard，替已建立骨架的角色配置 Rigidbody、Collider 與 Character Joint，讓角色死亡或失去控制時產生布娃娃物理。它不是一按就憑空生出人體。
Terrain
建立 Unity Terrain 地形，可雕刻高度、繪製地表材質並放置草與樹。適合戶外大型地面，不是普通 Plane 的華麗皮膚。
Tree
建立 Tree Editor 使用的樹木資產／物件，可配置樹幹與枝葉，之後可放進 Terrain。是否出現或推薦使用，會受 Unity 版本與渲染流程影響。
Wind Zone
建立風力區域，主要影響支援風擺動的樹木、植被與部分粒子效果。它不會自動把場景裡所有 Rigidbody 吹走。
05

複製物件：Ctrl + D

Hierarchy 中使用
選取 GameObject 後按 Ctrl+D，會複製所選的場景物件；複製品通常保留相同的 Component、Transform 與子物件結構。
Project 中使用
選取 Asset 後按 Ctrl+D，複製的是該資產檔案。快捷鍵相同，結果依目前選取的視窗與項目而定。
macOS
對應快捷鍵為 Command+D。
複製不是建立關聯

一般 Duplicate 會得到另一份物件或資產，不代表兩者之後會自動同步。需要可重複且集中管理的物件結構時，應理解 Prefab，而不是養出一群外表相同、內部各自叛變的複製品。

06

父子物件 Parent / Child

在 Hierarchy 中把一個 GameObject 拖到另一個 GameObject 上，前者就會成為後者的子物件。也可以先選定父物件，再使用建立子物件的操作，把新物件直接放在其階層底下。

父物件 Parent
位於階層上層的 GameObject，作為子物件 Transform 的參考座標。
子物件 Child
位於父物件底下的 GameObject。它仍可擁有自己的 Component，也可以在父物件範圍內獨立調整 Local Transform。
父物件移動
子物件會跟著一起移動。
父物件旋轉
子物件會受到父物件旋轉影響，並繞著階層中的參考點一起改變世界位置與方向。
父物件縮放
子物件的世界尺寸與位置通常也會受到影響。
Local Position
子物件相對於父物件的位置。Inspector 中子物件的 Transform 數值主要以父物件為參考，不再只是相對於世界原點。
一句話記憶父物件控制整組的座標基準；子物件繼承父物件的變換，但仍保有自己的 Local Transform。
不要只理解成「它們會一起移動」

一起移動只是最表面的結果。真正發生的是子物件的 Transform 被放進父物件的座標系統，因此移動、旋轉與縮放都可能沿著階層傳遞。

父子關係也不是普通資料夾

Hierarchy 可以用來整理，但 Parent / Child 會實際改變 Transform 計算。若只想把多個物件組成一組，通常會建立 Empty GameObject 當群組，並讓它的 Position、Rotation 與 Scale 保持可預期。
