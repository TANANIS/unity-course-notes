ch3_2 Unity3D 生命週期程式說明

這堂沒有新增新的生命週期事件，而是用一個測試腳本搭配 Debug.Log，實際驗證上一堂的生命週期呼叫順序，以及 Component 被移除時會發生什麼事。

LIFECYCLE · DEBUG.LOG

把上一堂的流程圖真的跑一次

將測試腳本掛到場景物件，按下 Play，再從 Console 觀察初始化、持續更新與銷毀階段的事件。

01測試腳本每個事件印出名稱 02按下 Play觀察初始化與更新 03移除 ComponentOnDisable → OnDestroy 04新版 Unity 校正DestroyObject → Destroy
01

測試方式：每個生命週期事件都印到 Console

老師建立 TestLifeCycle，讓各個生命週期方法只做一件事：用 Debug.Log 印出自己被呼叫了。

public class TestLifeCycle : MonoBehaviour
{
    public bool isDestroy;

    void Awake()
    {
        Debug.Log("Awake");
    }

    void OnEnable()
    {
        Debug.Log("OnEnable");
    }

    void Start()
    {
        Debug.Log("Start");
    }

    void Update()
    {
        Debug.Log("Update");

        if (isDestroy)
        {
            DestroyObject(this);
        }
    }

    void FixedUpdate()
    {
        Debug.Log("FixedUpdate");
    }

    void OnDisable()
    {
        Debug.Log("OnDisable");
    }

    void OnDestroy()
    {
        Debug.Log("OnDestroy");
    }
}
這堂的方法不是再背一次流程圖，而是用 Console 直接看 Unity 何時呼叫每個事件。
02

按下 Play：先初始化，再進入持續更新

老師把腳本拖到場景物件上並按下 Play，Console 先看到初始化事件，之後才開始持續出現更新事件。

Awake
↓
OnEnable
↓
Start
↓
FixedUpdate / Update 持續被呼叫
不要過度解讀 Console 排列

FixedUpdate 和 Update 並不是永遠一比一交替。前者跟固定物理時間步走，後者跟 frame 更新走；這堂只是在實際觀察兩者都會持續執行。

03

勾選 isDestroy：觀察 Component 結束生命週期

腳本公開了一個 isDestroy 布林值。老師在 Inspector 勾選後，Update() 裡的條件成立並移除目前這個 Script Component。

if (isDestroy)
{
    DestroyObject(this);
}

接著可以從 Console 看到：

OnDisable
↓
OnDestroy

這驗證了上一堂的概念：Component 離開啟用狀態時先進入 OnDisable()，真正銷毀時再進入 OnDestroy()。

這堂真正看到的事生命週期方法不是我們自己排著呼叫，而是 Unity 在狀態改變時主動呼叫。
04

新版 Unity 校正：不要再使用 DestroyObject

課程使用的是舊寫法 DestroyObject(this)。現在直接使用 Destroy：

Destroy(this);       // 只移除目前這個 Component
Destroy(gameObject); // 銷毀整個 GameObject

這裡的 this 指目前這個 TestLifeCycle Component，不是整個 GameObject。這個差異比舊 API 名稱本身更值得記。
