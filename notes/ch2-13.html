ch2_13 封裝 get 與 set

上一堂用 GetAttackPower() 與 SetAttackPower() 控制 private 欄位；這堂改用 C# 的 Property 語法，把讀取、設定與驗證集中在同一個名稱下。

PROPERTY

外面看起來像欄位，裡面仍然能控制讀寫

get 負責讀取，set 負責設定；在 set 裡，value 代表外部正在傳進來的新值。

01為什麼換寫法比 Get/Set 方法精簡 02Property 語法get / set 03value 是什麼外部傳入的新值 04set 裡做驗證等級不可小於 0 05外部怎麼使用像變數一樣讀寫 06五歲版理解同一扇門，門把更漂亮
01

上一堂已經能封裝，為什麼還要 get / set？

上一堂的做法是另外建立兩個公開方法：

weapon.SetAttackPower(90);
Debug.Log(weapon.GetAttackPower());

這當然可以運作，但 C# 還提供 Property 語法，讓外部使用時更接近一般變數，同時仍能保留封裝與驗證。

這堂目的不是取消封裝，而是把「公開讀寫入口」寫得更集中、更像一般欄位。
02

Property 的基本結構

老師用「等級限制」示範這種寫法。字幕中的實際命名有辨識誤差，以下依其邏輯整理：

private int _levelLimit;

public int LevelLimit
{
    get
    {
        return _levelLimit;
    }

    set
    {
        _levelLimit = value;
    }
}
private int _levelLimit
真正保存資料的私有欄位。
public int LevelLimit
公開 Property，外部透過這個名稱讀寫資料。
get
當外部讀取 LevelLimit 時執行，通常回傳私有欄位。
set
當外部對 LevelLimit 賦值時執行。
03

set 裡的 value 是什麼？

value 是 C# 在 set 區塊中提供的固定名稱，代表外部這次傳進來的新值。

kingSword.LevelLimit = 50;

當這行執行時，可以把流程想成：

50
 ↓
LevelLimit 的 set
 ↓
value == 50
 ↓
_levelLimit = value;
一句話記憶set 裡的 value = 外面等號右邊正在塞進來的那個值。
04

Property 一樣可以做資料驗證

老師延續上一堂的封裝概念，在等級限制的 set 裡加入「不可小於 0」的限制。

private int _levelLimit;

public int LevelLimit
{
    get
    {
        return _levelLimit;
    }

    set
    {
        if (value < 0)
        {
            Debug.Log("等級限制不可小於 0");
            _levelLimit = 0;
            return;
        }

        _levelLimit = value;
    }
}

所以 Property 並不是單純把 private 欄位重新公開。真正重要的是：外部每次設定值時，都會先經過 set 裡的規則。

封裝仍然存在外面看起來像直接賦值，實際上仍然先通過 set 的檢查。
05

外部使用時，看起來就像普通變數

// 寫入 → 呼叫 set
kingSword.LevelLimit = 50;

// 讀取 → 呼叫 get
Debug.Log(kingSword.LevelLimit);

老師特別強調這個優點：使用方式看起來很像前面直接操作 public 欄位，但背後其實仍有讀寫控制。

kingSword.LevelLimit = -100;

這時並不是毫無限制地把 -100 塞進私有欄位，而是先進入 set，再由裡面的判斷決定怎麼處理。

和上一堂的對照

SetAttackPower(90) / GetAttackPower() 是方法式封裝；LevelLimit = 90 / LevelLimit 是 Property 式封裝。核心目的相同，差別主要在語法與使用方式。

06

五歲版：門還是同一扇，只是門把變漂亮了

上一堂已經把真正資料鎖進寶箱，再用 Get / Set 方法當管理員。這堂沒有推翻那一套，只是把管理員的操作方式改得更像普通變數。

上一堂：你要明確叫管理員

weapon.SetAttackPower(90);
weapon.GetAttackPower();

可以想成：「管理員，我要放 90 進去。」以及「管理員，幫我拿目前的攻擊力出來。」

這一堂：Property 讓外面看起來像直接用變數

kingSword.LevelLimit = 50;
Debug.Log(kingSword.LevelLimit);

表面上看起來好像又能直接碰資料，但其實真正的 _levelLimit 仍然鎖在裡面。

外面看起來：

LevelLimit = 50

        ↓ 實際上

50 → set → 檢查 → _levelLimit 🔒

讀取 LevelLimit

        ↓ 實際上

_levelLimit 🔒 → get → 把值交出去

get：你想看？我拿給你

get
{
    return _levelLimit;
}
get 直覺版你想知道寶箱裡是多少？我幫你拿出來看。

set：你想改？先交給我

set
{
    _levelLimit = value;
}

set 就是寫入入口。外面並沒有直接碰到 _levelLimit，而是把新值交給 set。

set 直覺版你想改寶箱裡的東西？先交給我，我決定怎麼放。

value：你這次拿來想塞進去的東西

kingSword.LevelLimit = 50;
                         ↑
                       value

kingSword.LevelLimit = 100;
                         ↑
                       value

所以看到 value 不需要把它想成什麼神祕變數。它就是這一次外面等號右邊送進來的新值。

value 直覺版value = 你這次拿來想放進寶箱的東西。

兩堂課合起來

封裝：
我的資料不准你直接碰，你要經過我。

private：
把真正的資料鎖起來。

Get 方法 / get：
你想知道裡面是什麼？我拿給你看。

Set 方法 / set：
你想改？先交給我，我檢查完再放。

value：
你這次拿來想塞進去的新值。
第一堂與第二堂的差別

第一堂使用 GetLevel() / SetLevel(50) 這類公開方法；第二堂改用 Level / Level = 50。門還是同一扇門，封裝目的也沒變，只是 Property 把門把做得更好用。

關於 Inspector

老師在這堂把這種 get / set 寫法與 Unity Inspector 的設定情境連在一起說明；但目前字幕不足以完整還原其具體顯示條件，因此這裡先只保留「可在讀寫時加入額外處理」這個核心觀念，不把 Property 是否顯示在 Inspector 寫成固定規則。

五歲版結論外面看起來像在操作變數，但讀的時候其實走 get，寫的時候其實走 set；真正資料仍然藏在 private 裡。
本堂結論Property = 用 get 控制讀取、用 set 控制寫入；set 裡的 value 就是外部傳進來的新值。
