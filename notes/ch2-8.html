ch2_8 方法

方法（Method）可以把一段工作包成可重複呼叫的程式區塊。這堂重點是理解方法名稱、參數、回傳值，以及呼叫方法時資料如何進出。

METHOD

把一段工作取名字，之後再呼叫它

方法可以把較長的程式拆成有意義的小區塊，提升可讀性與重複利用。方法不會因為「寫好了」就自動執行，還需要被呼叫。

01

方法的基本結構

void Jump()
{
    Debug.Log("跳跳跳");
}
void
表示這個方法沒有回傳值。
Jump
方法名稱，用來描述這段程式負責做什麼。
()
參數列表；空的小括號代表這個方法目前不需要傳入資料。
{ ... }
方法實際執行的內容。
方法放在哪裡？

課堂提醒：方法要宣告在 class 裡，但不會再宣告在另一個方法裡。像 Start() 與自訂的 Jump() 都是同一層級的方法。

02

方法要被呼叫才會執行

void Start()
{
    Jump();
}

void Jump()
{
    Debug.Log("跳跳跳");
}

只宣告 Jump() 並不會自己發生事情。必須在 Start() 或其他地方使用 Jump(); 呼叫它。

一句話記憶宣告方法是在定義「可以做什麼」；呼叫方法才是真的「去做」。
03

有回傳值的方法

private float _hp = 100f;

float GetHP()
{
    return _hp;
}

如果方法需要把資料送回呼叫端，就不能使用 void，而要宣告實際回傳的型別。

float myHp = GetHP();
float
這裡表示 GetHP() 會回傳一個浮點數。
return
把值傳回呼叫端，並離開目前方法。
float myHp = GetHP();
用同樣能承接回傳值的型別接住結果。
return 之後

課堂提醒，執行到 return 後就會離開方法，因此同一路徑上寫在它後面的程式不會再被執行。

04

方法也可以接收參數

private float _hp = 100f;

void SetHP(float hp)
{
    _hp = hp;
}

參數讓呼叫端可以把資料交給方法。呼叫時：

SetHP(65f);

方法裡的 hp 就會收到 65f，再把它指定給欄位 _hp。

「有參數」和「有回傳值」是兩件獨立的事情。方法可以沒有參數、有參數、沒有回傳值，或同時有參數和回傳值。

05

參數和欄位同名時，可以使用 this

老師示範如果欄位與參數都叫 hp：

private float hp = 100f;

void SetHP(float hp)
{
    hp = hp;
}

這樣左右兩邊都指向方法參數，並沒有修改物件本身的欄位。

如果真的要同名，可以明確寫：

void SetHP(float hp)
{
    this.hp = hp;
}
this.hp
代表目前這個物件自己的 hp 欄位。
hp
在這個方法裡優先指向參數 hp。

課堂也用底線命名欄位（例如 _hp）來避免名稱混淆。

06

Unity Inspector：Script 初始值、序列化值與 Runtime 值

老師在示範 HP 時碰到一個很重要的 Unity 特性：Inspector 顯示的欄位不只是把 Script 裡的數字照抄出來。當欄位被 Unity 序列化後，Scene 或 Prefab 可以保存這個 Component 自己的數值。

Inspector 可以保存與 Script 不同的值

public float hp = 500f;

第一次加入 Component 時，Inspector 可能從 Script 的初始值取得 500。但如果之後在 Inspector 手動改成 20，這個 20 會成為該 Component 保存的序列化資料。

因此之後即使把程式碼改成：

public float hp = 999f;

已經存在於 Scene / Prefab 裡的 Component 仍可能保持 Inspector 原本保存的 20，而不是自動跟著變成 999。

不要記成「執行時一定以 Script 為主」

比較精確的理解是：Inspector 的序列化資料會決定 Component 載入時的欄位值；遊戲開始後，如果程式又對欄位重新賦值，就以最新的 Runtime 值為準。

執行期間誰最後賦值，現在的值就是誰

public int hp = 500;

void Start()
{
    hp = 100;
}

假設 Inspector 保存的是 20，遊戲開始載入時 hp 先會是 20；接著 Start() 執行 hp = 100;，Runtime 中的值就變成 100，Inspector 在 Play Mode 也會反映目前這個執行中數值。

void Update()
{
    hp = 100;
}

如果程式每幀都把 hp 設回 100，就算 Play Mode 中手動在 Inspector 改成 50，下一幀仍會再次被程式改回 100。這不是 Script 有某種永遠較高的「優先權」，而是程式又執行了一次賦值。

Script 初始值
例如 public int hp = 500; 裡的 500，是欄位建立時的初始設定，不代表所有既存 Component 永遠跟著這個數字。
Inspector 序列化值
Scene / Prefab 可以替某個 Component 保存自己的欄位資料，例如 HP = 20。
Runtime 值
Play 後目前記憶體裡真正的值；程式執行期間再次賦值時，它會繼續改變。

HideInInspector 與 private

[HideInInspector]
public float hp;

private float _hp;
[HideInInspector]
老師用它示範把欄位從 Inspector 隱藏。只是隱藏顯示，不代表之前保存的序列化值因此被清除。
private
一般情況下不會直接出現在 Inspector；老師後續把示範欄位改成 private，避免直接從 Inspector 修改。
Unity 重點Inspector 保存的是 Component 的序列化資料，不是單純觀看 Script 初始值；進入 Runtime 後，欄位再由實際執行的程式持續讀寫。
本堂結論方法把工作包成可呼叫的區塊；參數把資料送進去，return 把結果送回來。
