ch3_27 Coroutine_程式說明1

這堂把上一堂「Coroutine 可以做到一半暫停、之後再繼續」真正寫成程式：Coroutine 方法使用 IEnumerator，啟動後先執行前半段，遇到 yield return new WaitForSeconds(3) 時暫停約三秒，再從下一行繼續。

IENUMERATOR · STARTCOROUTINE · YIELD RETURN · WAITFORSECONDS

先做 A，停三秒，再從原地繼續做 B

ELI5：普通方法通常一路往下跑完；Coroutine 可以在中途放一張「先等等」的小紙條。Unity 看到 yield return，就先把這段流程停住，等指定時間到了，再回到下一行繼續。

01

執行結果：先出現第一個 Log，約三秒後才出現第二個

課程先直接跑範例。Coroutine 一開始會先印出第一個訊息，接著暫停，約三秒後再印出第二個訊息。老師也用時間差觀察，確認中間大約經過三秒。

先看懂結果Coroutine 不是整段停住遊戲，而是這段流程在等待後，再從原本的位置繼續。
02

Coroutine 方法不是 void，而是回傳 IEnumerator

老師特別指出，這種 Coroutine 方法要寫成會回傳 IEnumerator 的形式。方法名稱可以自己取，重點是這個方法本身要是 Coroutine 能使用的形式。

IEnumerator MyCoroutine()
{
    // Coroutine 內容
}

ELI5：現在先把 IEnumerator 記成「這是一種可以在中途 yield、之後再繼續的方法」。這堂重點是流程，不是去深挖 IEnumerator 在 C# 底層到底怎麼實作。

IEnumerator這堂把它當成 Coroutine 方法需要的回傳型別來使用。
03

啟動 Coroutine：開始跑這個 IEnumerator 方法

課程會先啟動 Coroutine，再讓那個 Coroutine 方法開始執行。字幕沒有可靠保存老師原本的識別字，因此下面只保留等價流程：

StartCoroutine(MyCoroutine());
啟動 Coroutine
      ↓
開始跑 MyCoroutine()
      ↓
先執行 yield 前面的程式
字幕限制

字幕能確認「先啟動 Coroutine，再執行 Coroutine 方法」這個流程，但原始類別名與方法名辨識不可靠，所以筆記使用概念名稱示意。

StartCoroutine它負責把 Coroutine 流程啟動起來。
04

yield return：程式跑到這裡先停，之後再從下一行繼續

這堂真正的關鍵是 yield return。Coroutine 執行到這裡時，不會把後面的程式一次跑完，而是先暫停這段 Coroutine，等等待條件完成後，再從下一行接著執行。

IEnumerator MyCoroutine()
{
    Debug.Log("1");

    yield return ...;

    Debug.Log("2");
}

先停
  ↓
條件完成
  ↓
從下一行繼續
  ↓
Log 2
yield return它是 Coroutine 的「先停在這裡，之後再接著跑」。
05

WaitForSeconds(3)：這次的等待條件就是約三秒

老師這堂用的是等待三秒：

yield return new WaitForSeconds(3);

ELI5 可以直接讀成：

yield return
＝ 這段 Coroutine 先暫停

new WaitForSeconds(3)
＝ 等待條件是約 3 秒

因此如果某些程式一定要三秒後才執行，就把它們寫在這個等待敘述後面。

先做 A
  ↓
yield return new WaitForSeconds(3)
  ↓
等約 3 秒
  ↓
做 B
做 C
做 D
WaitForSeconds這堂用它告訴 Coroutine：「先等約三秒，再繼續往下跑」。
06

和 Invoke 比：Invoke 比較簡單，Coroutine 比較有彈性

老師把這個範例和前面的 Invoke 放在一起比較。Invoke 的寫法比較簡單，主要是指定方法名稱與 Delay；Coroutine 寫法比較繞一點，但等待前後可以放更多流程，因此彈性更大。

Invoke
＝「幾秒後幫我呼叫這個方法」

Coroutine
＝「先做 A
   → 等三秒
   → 做 B
   → 做 C
   → 做 D」
取捨Invoke 簡單；Coroutine 稍微麻煩，但更適合描述一整段有等待節點的流程。
