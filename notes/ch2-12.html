ch2_12 封裝

上一堂為了方便示範，把 Weapon 的資料欄位設成 public；這堂開始處理它帶來的問題：外部程式可以任意塞入無效資料。老師用「攻擊力不應小於 0」說明封裝的目的。

ENCAPSULATION

不要讓外部直接碰資料，改由類別自己把關

先把真正保存資料的欄位改成 private，再提供公開方法讀取與設定。如此一來，所有寫入都必須經過同一個入口，也就能加入檢查規則。

01

為什麼欄位全部 public 不是好事？

上一堂外部類別可以直接寫：

kingSword.attackPower = 100;

方便歸方便，但同樣也能寫出：

kingSword.attackPower = -90;

如果遊戲規則要求攻擊力不能是負數，公開欄位本身沒有任何入口可以統一阻止這種寫入。老師實際測試後，數值確實會保持 -90。

問題核心public 欄位讓外部可以直接改資料，也就繞過了類別本身原本可能想維持的規則。
02

第一步：把真正的資料改成 private

老師的封裝做法第一步，就是把攻擊力欄位改成私有，讓其他類別不能再直接碰它。

public class Weapon
{
    private float _attackPower;
}

改成 private 後，外部原本這種寫法就不能用了：

// 外部類別不能再直接存取
// kingSword._attackPower = -90;
封裝不是單純「藏起來」

老師接下來沒有停在 private，而是另外提供公開方法。重點不是讓資料永遠碰不到，而是讓存取必須走指定入口。

03

第二步：用公開方法取得與設定私有欄位

字幕中的方法名稱辨識不完整，以下用等價命名整理老師的做法：

public class Weapon
{
    private float _attackPower;

    public float GetAttackPower()
    {
        return _attackPower;
    }

    public void SetAttackPower(float attackPower)
    {
        _attackPower = attackPower;
    }
}
private _attackPower
真正保存攻擊力的資料，外部不能直接修改。
GetAttackPower()
公開的讀取入口，把目前攻擊力回傳給外部。
SetAttackPower(...)
公開的設定入口，外部想改攻擊力時必須透過這裡。

於是外部使用方式從直接碰欄位：

kingSword.attackPower = 90;

改成呼叫方法：

kingSword.SetAttackPower(90);
Debug.Log(kingSword.GetAttackPower());
04

真正的價值：所有寫入都能先經過檢查

有了統一的設定入口，老師就在設定方法裡加入「攻擊力不可小於 0」的判斷。字幕中的完整程式沒有乾淨保留下來，以下保留其邏輯：

public void SetAttackPower(float attackPower)
{
    if (attackPower < 0)
    {
        Debug.Log("攻擊力不可小於 0");
        _attackPower = 0;
        return;
    }

    _attackPower = attackPower;
}

這樣外部即使嘗試：

kingSword.SetAttackPower(-90);

也不會再讓真正保存資料的 _attackPower 留在不合理的負數狀態；老師的示範會印出錯誤訊息，並讓攻擊力落在允許的值。

而傳入正常數值，例如 90，就會正常設定並讀回。

封裝的價值不是為了多寫兩個方法，而是讓「讀寫資料」有一個可以統一檢查、限制與控制的入口。
05

五歲版：把攻擊力想成鎖在寶箱裡的東西

這一節是理解用比喻，不是老師字幕原話。正式規則仍以前面的 private、Get / Set 與資料驗證為準。

全部 public：寶箱完全打開

寶箱
└── attackPower = 100

任何人都能直接伸手進去：
weapon.attackPower = 100;
weapon.attackPower = -9000;

只要欄位是 public，外面就可以直接改它。你想規定「攻擊力不能小於 0」，也沒有一個固定入口可以替你把關。

public 直覺版寶箱沒上鎖，別人想放什麼就放什麼。

private：先把寶箱鎖起來

寶箱 🔒
└── _attackPower

private 的意思可以先想成：「真正的資料不准外面直接碰。」但如果只鎖起來，外面也沒辦法正常使用，所以還需要管理員。

Get / Set：在寶箱前面放管理員

想放東西
   ↓
SetAttackPower()
   ↓
檢查規則
   ↓
_attackPower 🔒

想拿資料
   ↑
GetAttackPower()
   ↑
_attackPower 🔒

SetAttackPower() 像管理員說：「你想改攻擊力？先交給我，我檢查完再放進去。」

GetAttackPower() 則像管理員說：「你想知道裡面是多少？我拿給你看。」

所以封裝到底是什麼？

不是：
把資料藏起來，誰都不准碰

而是：
把資料藏起來
      +
提供自己設計好的入口
      +
所有人都必須經過入口的規則
五歲版結論封裝 = 我的東西不准你直接碰；你要讀或改，都先經過我設計的門。
下一堂會發生什麼？

現在的門叫 GetAttackPower() / SetAttackPower()，可以用，但寫久了很囉嗦。下一堂 C# Property 會把同一套封裝概念改成更像一般欄位的 get / set 語法。

本堂結論封裝 = 把資料設為 private，再提供受控制的公開入口，避免外部直接把物件改成不合法狀態。
