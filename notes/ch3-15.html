ch3_15 Lerp_程式說明

上一堂說 Lerp 是「A 往 B 靠近一點」。這堂把同一個想法真的套到數字、顏色、位置和旋轉上。東西不同，玩法其實沒變。

MATHF · COLOR · VECTOR3 · QUATERNION · LERP

四種 Lerp，其實都在做同一件事

先告訴 Unity「我現在在哪裡」，再告訴它「我要去哪裡」，最後給一個比例，Unity 就幫你找出這次應該走到哪。

01測試準備Material 與目標旋轉 02Mathf.Lerp數字往 100 靠近 03Color.Lerp顏色慢慢變藍 04Vector3.Lerp位置往目標靠近 05Quaternion.Lerp旋轉往 180° 靠近 06共同模型現在、目標、比例
01

先準備顏色和旋轉要用的東西

float lerpNumber = 0;
Material materialComp = null;
Quaternion euler;

void Start()
{
    materialComp = GetComponent<Renderer>().material;
    euler = Quaternion.Euler(new Vector3(0, 180, 0));
}

materialComp 是等等要改顏色的材質；euler 則先存好一個「Y 軸轉到 180°」的目標旋轉。

先準備顏色要有 Material；旋轉要先準備一個目標 Quaternion。
02

Mathf.Lerp：把數字一直往 100 拉

lerpNumber = Mathf.Lerp(lerpNumber, 100, 0.5f);
Debug.Log(lerpNumber);

把它想成有一條繩子，每次都把現在的數字往 100 拉一半：

0
↓ 拉剩下距離的一半
50
↓
75
↓
87.5
↓
93.75
↓
...

所以它不是每次固定加 10，也不是每次走固定距離。離 100 很遠時拉很多，越靠近 100，能拉的距離就越小。

課程後面也示範把固定的 0.5f 換成 Time.deltaTime，讓每一幀只靠近一小部分。

Mathf.Lerp數字版：「我現在是多少？我要變多少？這次靠近幾成？」
03

Color.Lerp：每一幀多混一點藍色

materialComp.color = Color.Lerp(
    materialComp.color,
    Color.blue,
    Time.deltaTime
);

五歲版可以直接想成調顏料：

現在的顏色
    +
偷偷混一點藍色
    ↓
新的顏色
    ↓
下一幀再混一點藍色
    ↓
越來越藍

第一個參數是現在的顏色，第二個參數是目標顏色 Color.blue，第三個參數告訴它這次要往藍色靠多少。

Color.Lerp不是「突然換色」，而是一直把現在的顏色往目標顏色混。
04

Vector3.Lerp：讓物件慢慢走向 (20, 0, 0)

transform.position = Vector3.Lerp(
    transform.position,
    new Vector3(20, 0, 0),
    Time.deltaTime
);

這次 A 和 B 不再是數字，而是兩個位置：

現在的位置 ●--------------------○ (20, 0, 0)
            ↓ 每幀往右靠一點
          ●------------------○
             ↓
             ●---------------○

因為每一幀都拿「新的現在位置」重新 Lerp，所以一開始靠近得明顯，之後越靠近目標，剩下的距離越小。

Vector3.Lerp把「數字往 100 靠」換成「位置往目標座標靠」，概念完全一樣。
05

Quaternion.Lerp：讓旋轉慢慢靠近 180°

transform.rotation = Quaternion.Lerp(
    transform.rotation,
    euler,
    Time.deltaTime * 2
);

transform.rotation 是現在的方向，euler 是 Start 裡先準備好的 Y 軸 180° 目標，最後的 Time.deltaTime * 2 則讓每幀靠近的比例比單純 Time.deltaTime 大一些。

現在朝這邊 →
       ↓ 每幀轉一點
        ↘
         ↓
          ← 目標 180°

課程把位置 Lerp 和旋轉 Lerp 同時開著，因此物件可以一邊移動、一邊轉向。

Quaternion.Lerp旋轉也只是另一種 A → B：目前旋轉 → 目標旋轉。
06

不要背四套 API，只記同一個三格盒子

Lerp(現在, 目標, 這次靠近多少)

Mathf.Lerp      → 數字
Color.Lerp      → 顏色
Vector3.Lerp    → 位置 / 向量
Quaternion.Lerp→ 旋轉

所以看到任何 Lerp，都先問三件事：

1. 我現在是什麼？
2. 我要變成什麼？
3. 這次往目標靠多少？
概念校正

像 Vector3.Lerp(current, target, Time.deltaTime) 這種「每幀把現在值再往目標拉一點」的寫法，會形成越來越慢的平滑逼近。它不是固定速度移動，也不要把 Time.deltaTime 理解成一加上去就自動變成完美的幀率無關運動。

這堂核心Lerp 的資料型別會變，但問題永遠是：現在 → 目標 → 取中間多少。
