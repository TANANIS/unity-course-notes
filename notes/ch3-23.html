ch3_23 event_2（事件使用方式）

上一堂只先知道 Event 是「宣布某件事發生了」。這堂把完整流程補起來：先用 delegate 規定能被註冊的方法長相，再建立 event，接收端用 += 訂閱、用 -= 退訂，最後由發送端一次通知所有已註冊的方法。

DELEGATE · EVENT · SUBSCRIBE · ONENABLE · ONDISABLE

先規定誰能加入，再讓大家訂閱同一個廣播

ELI5：Event 可以先想成一個廣播頻道。想收到通知的方法要先符合 delegate 規定的「方法長相」，再把自己登記進去。事件一觸發，所有已登記的方法就一起收到通知與參數。

01

場景先證明一件事：沒有父子關係，也能一起收到事件

課程準備了數個彼此平行、沒有父子階層關係的物件。發送端送出事件後，兩個接收端都會收到同一個「刪除」事件，並依照傳入的秒數延遲後刪除自己。

發送端
   │
   └──「刪除事件發生了，延遲 5 秒」
                ↓
              Event
           ↙         ↘
       接收物件 A   接收物件 B
           ↓            ↓
        5 秒後刪除    5 秒後刪除

這正好接回上一堂：Event 不需要靠 Transform 的父子階層來決定誰能收到通知。

場景重點彼此平行的物件，只要有訂閱同一個 Event，就能一起收到通知。
02

delegate：先規定「可以被註冊的方法，要長什麼樣子」

老師這堂反覆強調「方法的樣子」。範例中的方法規格是：沒有回傳值，而且會接收一個整數參數。

delegate void 某個Delegate(int value);

ELI5：把 delegate 想成一個插座規格。只有插頭長得對的方法，才能插進這個位置。

規格要求：

回傳值：void
參數：一個 int

所以符合的形狀是：
void 某方法(int value)

重點不是方法叫什麼，而是它的回傳值與參數形式要符合這個 delegate 定義。

字幕限制

字幕把實際 delegate、event 與方法名稱辨識得很不穩定，因此這篇只保留課堂能確定的「方法規格」與流程；程式碼識別字改用概念名稱，不假裝還原老師原始命名。

delegate它先定義一種方法規格：哪些方法的「長相」有資格被放進來。
03

event：建立一個只能放「符合規格方法」的事件

接著老師宣告一個靜態事件，事件使用前面定義好的 delegate 型別。概念上就是：

public delegate void DeleteAction(int seconds);
public static event DeleteAction DeleteEvent;

上面的名稱是為了方便理解而重新命名，但結構對應課堂內容：DeleteAction 規定方法必須是 void + 一個 int；DeleteEvent 則負責保存符合這個規格、而且已經註冊進來的方法。

ELI5：

delegate
＝ 會員資格
＝「方法必須長這樣」

Event
＝ 會員名單 / 廣播頻道
＝「符合資格的方法可以登記進來」
eventdelegate 先定規格，event 再保存符合規格、已經訂閱的方法。
04

觸發 Event：一次把參數送給所有已註冊的方法

課程在 Update 裡檢查 Inspector 的勾選狀態。條件成立時，就觸發事件並把設定好的整數值一起傳出去。

if (DeleteEvent != null)
{
    DeleteEvent(seconds);
}

這段是依照字幕內容重寫的等價示意。老師也特別提醒，事件目前可能沒有任何方法註冊，所以呼叫前要先確認它不是空的。

ELI5：不是發送者自己跑去找每一個接收物件，而是：

「刪除事件發生了！」
        +
「這次的數值是 5」
        ↓
      Event(5)
        ↓
所有已訂閱的方法一起被叫
        ↓
每個方法都收到 5

課程還會在觸發後把勾選狀態關掉，避免 Update 每一幀都重複觸發同一個事件。

觸發呼叫 Event 一次，就會把同一個參數送給所有已註冊、而且符合 delegate 規格的方法。
05

+= 是訂閱；-= 是退訂，而且課程放在 OnEnable / OnDisable

接收端會在 OnEnable 裡把自己的方法註冊進事件，在 OnDisable 裡再取消註冊。

void OnEnable()
{
    Sender.DeleteEvent += DeleteMe;
}

void OnDisable()
{
    Sender.DeleteEvent -= DeleteMe;
}

void DeleteMe(int seconds)
{
    // 收到事件後，依 seconds 做刪除處理
}

ELI5：

OnEnable
＝ 我上線了
＝ 開始收這個頻道的通知
＝ +=

OnDisable
＝ 我下線了
＝ 不要再通知我
＝ -=

老師最後特別提醒，註冊與取消註冊這兩步不能漏掉，否則這套事件流程不會照預期工作。

訂閱生命週期OnEnable 用 += 加入通知名單；OnDisable 用 -= 把自己移出名單。
06

把整堂壓成六個動作

① delegate
「能來聽 Event 的方法，必須長這樣」
        ↓
② event
「建立一個通知頻道」
        ↓
③ += 方法
「我要訂閱」
        ↓
④ Event(參數)
「事情發生了，廣播出去」
        ↓
⑤ 所有訂閱方法被呼叫
「每個人都拿到同一份參數」
        ↓
⑥ -= 方法
「我不聽了，取消訂閱」

如果只剩五秒能複習，就記這個版本：

delegate = 方法規格
event    = 廣播頻道
+=       = 訂閱
Event()  = 廣播
-=       = 退訂
這堂核心delegate 規定能訂閱的方法長相；event 保存訂閱者；觸發時一次通知全部；物件啟用時訂閱、停用時退訂。
