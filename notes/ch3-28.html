ch3_28 Coroutine_程式說明2

這堂用 Coroutine 完成倒數計時，並刻意拆成兩個類別：一個類別提供倒數用的 IEnumerator，另一個類別取得那段 Coroutine，再交給 StartCoroutine 執行。倒數本身用 while 決定是否繼續，每一輪用 yield return new WaitForSeconds(1) 等待約一秒。

COROUTINE · WHILE · WAITFORSECONDS · CROSS CLASS

只要還沒倒數完，就做一次、等一秒、再回來判斷

ELI5：上一堂學的是「做到中間可以等」。這堂把等待塞進 while 裡，所以流程會變成：做一次 → 等一秒 → 回來檢查還要不要繼續。另一個類別只負責把這段流程拿來啟動。

01兩個類別一個提供流程，一個啟動 02while 倒數count > 0 才繼續 03每輪等一秒yield + WaitForSeconds 04跨類別啟動把 IEnumerator 交給 StartCoroutine 05和 InvokeRepeating 比取消 vs 條件結束 06實際用途怪物與障礙物生成 07整堂模型做 → 等 → 判斷 → 重複
01

老師故意拆成兩個 class，示範 Coroutine 可以把別處提供的流程拿來執行

這堂的範例不是把所有東西塞在同一個類別。課程把「倒數計時的 Coroutine」與「啟動 Coroutine」拆成兩個類別：一個專門提供倒數流程，另一個負責取得前者的元件並啟動它。

倒數類別
└─ 提供 Countdown() 這段 IEnumerator

啟動類別
└─ 取得倒數類別元件
   ↓
   取得 Countdown()
   ↓
   StartCoroutine(...)

ELI5：A 不一定要自己寫倒數流程，它可以去 B 那裡拿一份「倒數工作流程」，再叫 Unity 開始跑。

字幕限制

字幕裡兩個實際類別名與方法名辨識不可靠，因此筆記只保留能確定的結構：一個類別負責倒數，另一個類別取得它並啟動 Coroutine。

兩個 classCoroutine 流程可以由另一個類別提供，再交給 StartCoroutine 執行。
02

while 決定「還要不要再跑下一輪」

倒數方法本身會回傳 IEnumerator，裡面使用 while。課程的條件概念是：只要 count 還大於 0，就持續執行；當 count 變成 0，不再符合條件，while 就結束。

IEnumerator Countdown()
{
    while (count > 0)
    {
        // 顯示 / 處理目前的 count
        count--;

        yield return new WaitForSeconds(1);
    }
}

上面的識別字是依字幕流程整理的等價示意，重點是課堂中的控制結構：

10 > 0 → 繼續
9  > 0 → 繼續
8  > 0 → 繼續
...
1  > 0 → 繼續
0  > 0 → false
        ↓
while 結束
while它負責判斷這個 Coroutine 還要不要再跑下一輪。
03

每跑完一輪就 yield 一秒，所以倒數看起來是一秒跳一次

while 每跑完一次，課程會讓 Coroutine 暫停約一秒：

yield return new WaitForSeconds(1);

所以實際流程不是瞬間把數字全部減完，而是：

顯示 10 / count--
        ↓
等約 1 秒
        ↓
回到 while 判斷
        ↓
顯示 9 / count--
        ↓
等約 1 秒
        ↓
再回去判斷
        ↓
...

老師也用「跑十次就會累積十次等待」來說明：每一輪都有自己的等待時間。

yield + whilewhile 控制重複次數；yield return WaitForSeconds(1) 控制每輪之間的時間。
04

啟動端：取得另一個元件，再把它提供的 IEnumerator 交給 StartCoroutine

另一個類別的工作很單純：先取得提供倒數流程的元件，接著呼叫它的方法取得 IEnumerator，最後用 StartCoroutine 開始執行。

// 等價示意
StartCoroutine(otherComponent.Countdown());
啟動類別
   ↓
找到倒數元件
   ↓
取得 Countdown() 的 IEnumerator
   ↓
StartCoroutine(...)
   ↓
Unity 開始跑那段倒數流程

這就是課程這堂刻意拆成兩個類別要展示的重點。

跨類別啟動 Coroutine 的類別，不必就是定義那段 IEnumerator 的類別。
05

和 InvokeRepeating 比：一個靠取消，一個可以靠 while 條件自然結束

前面的 InvokeRepeating 倒數範例會持續重複呼叫，所以課程在倒數到 0 時用 CancelInvoke 停止。這堂 Coroutine 則把「是否繼續」直接寫進 while 條件裡。

InvokeRepeating
＝ 固定一直呼叫
→ 到停止條件時 CancelInvoke

Coroutine + while
＝ 條件成立才進下一輪
→ 條件 false，while 自然結束

這不是說哪一個永遠比較好，而是這堂讓你看到 Coroutine 可以把「重複、等待、結束條件」一起寫在同一段流程裡。

差異Coroutine 可以直接把停止條件寫成流程的一部分。
06

老師最後舉的用途：固定間隔生成怪物或障礙物

課程最後提到 Coroutine 很常用，除了倒數，也可以拿來控制怪物、障礙物等內容的週期性生成。

生成一次
   ↓
等待一段時間
   ↓
條件還成立？
   ↓ Yes
再生成一次
   ↓
再等待...

這堂沒有提供完整生怪程式碼，所以筆記只保留老師提到的使用方向，不另外補實作。

用途Coroutine 很適合描述「做一次 → 等一下 → 再做一次」的遊戲流程。
07

Coroutine 三堂課，到這裡可以合成完整模型

IEnumerator
＝ 一段可以暫停的流程

StartCoroutine
＝ 啟動那段流程

yield return
＝ 先停在這裡

WaitForSeconds(1)
＝ 每輪等待約一秒

while
＝ 決定還要不要再跑下一輪

跨類別
＝ 別的元件提供 IEnumerator
   也可以交給 StartCoroutine 執行

五秒複習版：

while (還沒結束)
{
    做一次
    ↓
    yield 等一下
    ↓
    回來重新判斷
}

整體：
做 → 等 → 判斷 → 重複 → 結束
這堂核心while 管「要不要繼續」，yield 管「多久後再繼續」；Coroutine 因此能把重複、等待與結束寫成一條完整流程。
