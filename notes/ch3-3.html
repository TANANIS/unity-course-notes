ch3_3 Vector_1（向量類介紹）

這堂開始進入 Unity 很核心的向量概念：Vector3 不只是三個數字，而可以拿來表達位置、方向與位移。老師先介紹座標方向、常用靜態向量，以及 magnitude、sqrMagnitude、normalized。

VECTOR3 · DIRECTION · LENGTH

先把 Vector3 想成一支「有方向、也有長度的箭頭」

這堂真正要建立的不是 API 清單，而是向量的直覺：一支箭頭同時包含「往哪裡」與「有多長」兩種資訊。

01Vector3 是什麼struct 與 XYZ 02Unity 座標方向X / Y / Z 03常用方向forward / up / right 04箭頭心智模型方向 + 長度 05magnitude真正長度 06sqrMagnitude長度平方 07normalized只保留方向
01

Vector3：三個數字組成的向量，而且它是 struct

老師先提醒，Unity 的 Vector3 是結構（struct），因此前面學過的值型別概念會繼續適用。3D 常用 Vector3，2D 則常用少一個 Z 軸的 Vector2。

Vector3 v = new Vector3(3, 4, 0);

// x = 左右
// y = 上下
// z = 前後

Vector3 可以拿來表示很多東西，例如位置、方向、速度與位移。型別相同，不代表它們的數學意義相同。

Vector3 position;   // 位置
Vector3 direction;  // 方向
Vector3 velocity;   // 速度
Vector3 offset;     // 位移
先建立這個直覺Vector3 不是單純的「三個 float」，而是遊戲世界裡描述空間關係的基本工具。
02

Unity 的 XYZ：右、上、前

老師用左手示範 Unity 的座標方向。這堂先記正負方向即可：

+X = 右     -X = 左
+Y = 上     -Y = 下
+Z = 前     -Z = 後

因此往前就是 Z 增加，往上就是 Y 增加，往右就是 X 增加。

03

常用靜態方向：不用每次自己寫 (0, 0, 1)

Unity 已經提供常見方向向量，而且它們是靜態成員，可以直接從 Vector3 類型使用。這也接回上一章學過的 static。

Vector3.forward  // ( 0, 0, 1) 前
Vector3.back     // ( 0, 0,-1) 後
Vector3.up       // ( 0, 1, 0) 上
Vector3.down     // ( 0,-1, 0) 下
Vector3.right    // ( 1, 0, 0) 右
Vector3.left     // (-1, 0, 0) 左

例如向前移動、向前發射子彈，可以用 Vector3.forward 表示方向；向上跳則可用 Vector3.up。

04

最重要的心智模型：把向量想成箭頭

如果只把 (3, 4, 0) 當成三個數字，後面的 magnitude 與 normalized 會很難記。比較好的方式是把它看成一支箭頭：

Vector3 v = (3, 4, 0)

它同時告訴我們：
1. 方向：箭頭往哪裡指？
2. 長度：這支箭有多長？

後面三個屬性，其實都只是在問這支箭頭不同的問題。

一支箭頭，兩種資訊向量 = 方向 + 長度。
05

magnitude：這支箭到底有多長？

老師說 magnitude 可以取得向量長度。用 (3, 4, 0) 當例子最容易看懂：

Vector3 v = new Vector3(3, 4, 0);
float length = v.magnitude;

// length = 5

因為它等同於一個 3、4、5 的直角三角形。換句話說，magnitude 是把方向暫時放一邊，只回答：

「這支向量箭頭有多長？」
magnitude我要知道真正的向量長度。
06

sqrMagnitude：不是另一種長度，只是「長度的平方」

這個名稱最容易嚇人，但概念其實沒有增加。剛才 v.magnitude = 5，那麼：

v.magnitude      // 5
v.sqrMagnitude   // 25，也就是 5²

為什麼要 25？因為有時候根本不需要知道真正距離，只需要比較誰比較長。

A 長度 = 5
B 長度 = 7

5 < 7
25 < 49

平方後，大小關係沒有改變。

老師的重點是：magnitude 需要做平方根運算，而 sqrMagnitude 不需要。如果只是比較兩個向量長度，可以直接比較平方長度。

if (a.sqrMagnitude < b.sqrMagnitude)
{
    // a 比 b 短
}
sqrMagnitude我要比較誰比較長，但我不需要知道真正長度是多少。
07

normalized：方向不變，把箭頭縮成長度 1

這是這堂最容易誤解的地方。老師把它簡化成「把向量歸一，只留下方向」，這個方向沒錯，但不要把它理解成每個 XYZ 都變成 ±1。

Vector3 v = new Vector3(3, 4, 0);
Vector3 direction = v.normalized;

v            = (3,   4,   0)   // 長度 5
direction    = (0.6, 0.8, 0)   // 長度 1

兩支箭頭仍然朝同一個方向，只是第二支被等比例縮短成長度 1。

原本：(3, 4, 0)
       ↗  同一方向，長度 5

歸一：(0.6, 0.8, 0)
       ↗  同一方向，長度 1
不要這樣背

(3, 4, 0).normalized 不是 (1, 1, 0)。normalized 的定義是「保留方向，把整個向量的長度變成 1」。

這在遊戲移動很重要。當我們只想取得「往哪走」，不希望原本向量長度偷偷影響速度時，可以先 normalized，再乘上我們真正想要的速度。

Vector3 direction = new Vector3(3, 4, 0).normalized;
Vector3 velocity = direction * 10;

// 純方向 × 自己指定的速度
normalized同方向，但長度固定成 1。可以把它想成「把力道拿掉，只留下純方向」。
08

三個最容易混的屬性，最後只背這三句

magnitude
= 長度

sqrMagnitude
= 長度²

normalized
= 同方向，但長度變 1

如果要再換成問題：

magnitude
→ 這支箭多長？

sqrMagnitude
→ 我只想比較誰比較長。

normalized
→ 我不在乎多長，只想知道往哪裡。
這堂核心Vector3 = 方向 × 長度；magnitude 看長度，normalized 看純方向。
09

講義下方的方法先知道名字即可

老師的整理表還列出 Cross、Dot、Distance、MoveTowards。這堂字幕最後只預告接下來會介紹方法，因此目前先保留名稱，不在這頁提前把後面的 Vector 課吃掉。

Vector3.Cross(...)
Vector3.Dot(...)
Vector3.Distance(...)
Vector3.MoveTowards(...)
