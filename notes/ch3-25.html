ch3_25 Invoke_程式說明

上一堂先認識 Invoke 系列像「鬧鐘」。這堂把它真正跑起來：先用 Invoke 延遲呼叫一次，再用 InvokeRepeating 做倒數計時，最後在倒數到 0 時用 CancelInvoke 停止重複呼叫。

INVOKE · INVOKEREPEATING · CANCELINVOKE · COUNTDOWN

真的把鬧鐘設起來：晚點做、重複做、到點就停

ELI5：上一堂是在看鬧鐘有哪些按鈕；這堂是在實際設定鬧鐘。Unity 先把方法排進時間表，時間到了再呼叫；如果是重複鬧鐘，就一直呼叫到你主動取消。

01延遲呼叫Invoke 約兩秒後執行 02量時間差不是精密到完全等於 2 秒 03倒數計時InvokeRepeating 每秒一次 04倒數到 0 停止CancelInvoke 05同類別限制被呼叫方法放在同一個 class 06Console 顯示Collapse 只是整理 Log 07整堂模型排程 → 呼叫 → 取消
01

Invoke 實作：先記錄時間，再延遲兩秒呼叫方法

課程先示範延遲呼叫。呼叫端先記下現在的時間，再把某個方法排定成大約兩秒後執行。

記下開始時間
    ↓
Invoke("DelayMethod", 2f)
    ↓
Unity 等待
    ↓
約兩秒後呼叫 DelayMethod()

ELI5：不是現在自己呼叫方法，而是對 Unity 說：「這個先幫我記著，兩秒後再叫它。」

Invoke 實作現在只負責排程；真正的方法呼叫留給 Unity 在延遲時間到後執行。
02

老師用時間差確認：實際結果大約是兩秒，不一定剛好卡在 2.000 秒

被延遲呼叫的方法執行時，課程會用「現在時間減掉剛才記錄的開始時間」來觀察實際經過多久。

開始時記下時間 A
        ↓
Invoke 延遲兩秒
        ↓
方法被呼叫時取得時間 B
        ↓
B - A
        ↓
大約 2 秒

課程實際觀察到的結果會在兩秒附近，有一點誤差，不會保證畫面上正好顯示完全等於兩秒。

時間觀察Invoke 的延遲在這個範例中是「大約兩秒後呼叫」，課程用時間差直接驗證結果。
03

InvokeRepeating 實作：把它拿來做每秒一次的倒數

第二個範例是倒數計時。先準備一個起始數字，再用 InvokeRepeating 讓倒數方法從 0 秒延遲開始、之後每秒呼叫一次。

InvokeRepeating(
    "Countdown",
    0f,
    1f
);

這段可以直接讀成：

第一次：不用等
之後：每 1 秒呼叫一次 Countdown

所以畫面上的概念就是：

5
↓ 1 秒
4
↓ 1 秒
3
↓ 1 秒
2
↓ 1 秒
1
↓
0
InvokeRepeating第一個時間決定多久後開始；第二個時間決定之後每隔多久再呼叫一次。
04

倒數到 0 就 CancelInvoke，不然它還會繼續減成負數

倒數方法每次被呼叫都把數字往下減。課程在數字等於 0 時取消這個重複呼叫，避免它繼續變成負數。

void Countdown()
{
    count--;

    if (count == 0)
    {
        CancelInvoke("Countdown");
    }
}

上面的識別字是依課程流程改成容易理解的示意名稱；字幕沒有可靠保留老師原本的方法名稱。

ELI5：

每秒敲門一次：
「減一！」

5 → 4 → 3 → 2 → 1 → 0

到 0：
「好了，不要再敲了。」
CancelInvoke(...)
停止條件重複呼叫不會自己知道何時該停；這個範例是在 count == 0 時主動取消。
05

這堂再次照課程規則：被 Invoke 呼叫的方法放在同一個 class 裡

課程再次提醒，這裡用方法名稱字串呼叫的方式，只處理同一個類別裡的方法，因此範例會把延遲方法與倒數方法都寫在同一支 class 裡。

同一個 class
├─ 呼叫 Invoke(...)
├─ DelayMethod()
└─ Countdown()
課程限制這堂的 Invoke 寫法，是在同一個 class 裡用方法名稱排程呼叫。
06

Console 的 Collapse 只是把重複 Log 疊在一起

課程示範倒數時順便提到 Console 的 Collapse。勾起來後，重複的 Log 會疊在一起並顯示次數；取消後則會逐筆列出。

這只是讓 Console 畫面比較乾淨，不會改變 Invoke 或倒數本身的執行方式。

旁支功能Collapse 只影響 Console 顯示方式，不是 Invoke 的一部分。
