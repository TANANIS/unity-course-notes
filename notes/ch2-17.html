ch2_17 靜態與非靜態

這堂課用最簡單的方式區分 static 與非 static：靜態成員屬於「類別」，非靜態成員屬於「物件」。因此兩者的呼叫方式，以及靜態方法裡能直接使用哪些成員，都不一樣。

STATIC

static 看類別，非 static 看物件

老師把這堂的判斷方式濃縮成一句話：靜態的是類別的，非靜態的是物件的。

01

static：屬於類別

老師把靜態成員稱為「類別的變數 / 方法」。使用時可以直接從類別名稱呼叫，不需要先建立物件。

public class PlayerData
{
    public static int HP = 100;
}

int hp = PlayerData.HP;
static靜態成員屬於類別本身，所以使用「類別名稱.成員」呼叫。
02

非 static：屬於物件

非靜態成員屬於某一個實際建立出來的物件，因此要先有物件，才能透過它使用成員。

public class Player
{
    public int HP = 100;
}

Player player = new Player();
int hp = player.HP;

不能只用類別名稱直接拿非靜態成員：

// 錯誤概念
Player.HP;
非 static先建立物件，再透過「物件.成員」使用。
03

靜態方法不能直接使用非靜態成員

老師特別強調：在 static 方法中，可以直接使用 static 變數或呼叫 static 方法，但不能直接使用某個物件才擁有的非靜態成員。

public class Player
{
    public static int TotalCount;
    public int HP;

    public static void PrintData()
    {
        Debug.Log(TotalCount); // 可以
        // Debug.Log(HP);      // 不可以直接這樣用
    }
}

反過來，非靜態方法則可以使用類別中的靜態成員。

規則static 方法 → 直接使用 static 成員；非 static 方法 → 可以使用物件成員，也可以使用 static 成員。
04

老師舉的應用：場景之間保留資料

課堂最後舉了一個 Unity 例子：角色從 A 場景切換到 B 場景時，如果希望某些資料，例如血量，在場景切換後仍然保留下來，可以把資料存放在靜態變數中。

public class PlayerData
{
    public static int HP = 100;
}

這一堂只先介紹 static 的基本用途；老師也說其他應用會在後續遇到時再補充。

05

五歲版：班級公用資料 vs 每個人的資料

static
= 全班共用的一塊白板
= 不需要先找某個同學
= 直接找「班級」就能看到

非 static
= 每個同學自己的筆記本
= 你必須先找到那個同學
= 才能看他的資料

所以先這樣記：

類別.成員
→ static

物件.成員
→ 非 static
五歲版結論static 是大家共用、掛在類別上的；非 static 是每個物件自己擁有的。
