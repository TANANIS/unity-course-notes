ch2_16 命名空間（namespace）

這堂處理一個很單純的問題：如果不同工程師剛好寫出同名的類別，C# 要怎麼知道你想用哪一個？答案就是用 namespace 把類別分到不同的命名空間，再透過 using 或完整名稱指定要使用哪一個型別。

NAMESPACE

同名沒關係，只要知道它屬於哪個空間

老師用 Howard 與另一位工程師都寫了一個 Cat 類別的例子，說明 namespace 可以替同名類別加上不同的「姓氏」，避免引用時混淆。

01

為什麼需要 namespace？

老師先假設兩個工程師都建立了一個叫 Cat 的類別。此時程式只看到 Cat，就無法單靠名稱判斷你要的是哪一個。

Howard 寫了一個 Cat
另一位工程師也寫了一個 Cat

現在寫：
Cat cat = new Cat();

問題：到底是哪一個 Cat？

namespace 的作用，就是把同名類別放到不同的命名空間中，讓它們可以被區分。

這堂核心namespace = 替類別分組，避免不同地方出現同名型別時撞名。
02

namespace：把類別放進不同空間

字幕中的實際命名辨識有些混亂，以下保留老師「Howard 的 Cat」與「另一組 Cat」的概念，用乾淨的示意名稱整理：

namespace Team.Howard
{
    public class Cat
    {
    }
}

namespace Team.Other
{
    public class Cat
    {
    }
}

現在兩個類別雖然都叫 Cat，但完整名稱已經不同：

Team.Howard.Cat
Team.Other.Cat
03

using：告訴程式「這裡預設先用這個命名空間」

老師示範可以在程式上方加入 using。假設寫：

using Team.Howard;

那麼下面只寫簡短名稱 Cat 時，就可以直接使用這個命名空間裡的 Cat：

using Team.Howard;

Cat cat = new Cat();
using把某個 namespace 引入目前檔案後，就可以少寫前面的完整路徑。
04

需要指定另一個同名類別時，就直接「指名道姓」

即使上方已經寫了 using Team.Howard;，仍然可以在某一行直接寫完整名稱，明確指定另一個 Cat：

using Team.Howard;

Cat howardCat = new Cat();
Team.Other.Cat otherCat = new Team.Other.Cat();

老師把這種寫法形容成「指名道姓」：平常用 using 省略前綴；真的需要區分同名型別時，就把完整 namespace 寫出來。

課堂後續

老師也提到後面的 Unity UI 章節會大量看到 using，例如引用按鈕、文字等相關類別時，就會再次碰到這個概念。

05

五歲版：班上有兩個都叫小明的人

一年一班的小明
二年二班的小明

兩個都叫「小明」沒有問題，
因為前面還有班級可以區分。

namespace 就像班級名稱：

Team.Howard.Cat
Team.Other.Cat

using Team.Howard; 則像是先說：

「接下來我說 Cat，預設是在講 Howard 這組的 Cat。」

如果突然要講另一個，就把全名寫出來：

Team.Other.Cat
五歲版結論namespace = 類別的「姓氏／地址」；using = 先告訴程式這個檔案平常要用哪一組。
