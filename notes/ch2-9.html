ch2_9 call_by_ref

這堂在處理一個核心問題：把變數傳進方法時，方法拿到的是「值的副本」，還是可以直接改到呼叫端原本的變數？重點是 Call by Value、ref 與 out。

PARAMETER PASSING

副本、原本變數，以及輸出結果

先從普通參數開始，再看 ref 如何讓方法修改原本變數，最後理解 out 為什麼可以不先給初始值。

01Call by Value傳入值的副本 02ref修改原本變數 03out由方法輸出結果 04直覺理解影本 / 本人 / 寫答案 05三者比較普通 / ref / out 06Unity 後續用途Raycast Hit
01

Call by Value：方法拿到的是值的副本

void Start()
{
    int a = 80;
    SetA(a);
    Debug.Log(a); // 80
}

void SetA(int a)
{
    a = 20;
}

雖然 SetA() 裡把參數 a 改成 20，但 Start() 裡原本的 a 仍然是 80。

課堂的重點是：普通參數只是把「80 這個值」放進方法，而不是把外面那個變數 a 本身的位置交給方法。

一句話記憶Call by Value = 給方法一份值的副本；方法改副本，不會改到外面的原變數。
02

ref：讓方法直接修改呼叫端的變數

void Start()
{
    int a = 80;
    SetA(ref a);
    Debug.Log(a); // 20
}

void SetA(ref int a)
{
    a = 20;
}

改成 ref 後，方法裡修改 a，外面的 a 也會一起改變。

呼叫方法
SetA(ref a);，呼叫端要寫 ref。
宣告方法
void SetA(ref int a)，參數宣告也要寫 ref。
呼叫前
傳給 ref 的變數必須先有值，例如 int a = 80;。
為什麼兩邊都要寫 ref？

方法宣告是在說「我會用參考方式接這個參數」；呼叫端也必須明確表示「我要把這個變數用 ref 傳進去」。

03

out：這個值就是準備讓方法產生的

老師接著提出一個問題：如果 a 放進方法後一定會被重新設定，那為什麼還要先寫一個初始值？因此引出 out。

void Start()
{
    int a;
    SetA(out a);
    Debug.Log(a); // 20
}

void SetA(out int a)
{
    a = 20;
}
呼叫前不用初始化
int a; 就可以傳進 out，不必先寫成 int a = 80;。
方法內一定要賦值
out 代表這個參數要由方法輸出，因此方法結束前必須替它設定值。
兩邊都要寫 out
呼叫時寫 SetA(out a)，方法參數也寫 out int a。
和 return 的關係

如果方法只需要帶回一個結果，直接使用 return 通常更直觀。out 的價值在於方法還可以透過自己的回傳值表達其他資訊，同時再把額外結果放進 out 參數。

bool TryGetNumber(string text, out int number)
{
    // bool 可以表示成功或失敗
    // number 則透過 out 帶出結果
}
04

直覺版理解：把變數想成一張紙

下面不是老師字幕的原話，而是用來幫助理解的比喻。正式規則仍以前面三節為準。

普通參數：影印一份給方法

你手上有一張紙寫著 10。普通參數不是把原本那張紙交出去，而是影印一份給方法。

你的紙：10
方法的影本：10

方法把影本改成 100

你的紙：10
方法的影本：100
Call by Value給影本。方法怎麼改自己的影本，都不會改到你手上的原本。

ref：把原本那張紙交給方法

ref 不再是影印一份，而是直接告訴方法：「原本那張紙就在這裡，你直接改它。」

原本的紙：10
     ↑
外面的 a 與方法裡的參數都在操作這張紙

方法改成 100

原本的紙：100
ref給本人。方法改的就是外面原本那個變數。

out：給一張可以原本空白的紙，但一定要寫答案回來

out 的重點不是「唯一能把值帶出去」，而是這個變數可以一開始沒有答案，方法負責把答案寫進去。

外面的紙：空白

交給方法：請幫我寫答案

方法結束前：一定要寫值

帶回來：100
out請你寫答案回來。呼叫前可以沒有值，但方法離開前一定要給值。
為什麼有 return 還需要 out？

如果只要一個結果，通常直接 return 就好。out 常見於方法還需要用 return 表示其他事情，例如成功或失敗，同時再把實際結果透過 out 帶出去。

bool success = int.TryParse("123", out int number);

// success：有沒有成功
// number：成功後得到的數字
05

普通參數、ref、out 放在一起比較

普通參數
傳入值的副本；方法內重新指定參數，不會改到外面的變數。記法：給影本。
ref
讓方法可以讀取並修改外面的原變數；呼叫前必須先有值。記法：給本人。
out
主要用來由方法產生並輸出一個值；呼叫前不用初始化，但方法內必須賦值。記法：請你寫答案回來。
// 普通參數
SetA(a);

// ref
SetA(ref a);

// out
SetA(out a);
不要混成同一件事

這堂談的是「參數如何傳入方法」。現在先掌握普通、ref、out 的差異即可，不必把後面類別與 Reference Type 的概念提前攪進來。

06

Unity 後面會在哪裡看到 out？

老師預告之後講射線碰撞（Raycast）時會再次使用 out。射線撞到物件後，可以把碰撞結果輸出成 Hit 資料，再從中取得碰撞物件、位置 Point 等資訊。

RaycastHit hit;

// 後續 Raycast 章節會看到類似概念：
// Physics.Raycast(..., out hit)

這裡目前只需要記住用途：out hit 讓方法把「碰撞後得到的資料」交回呼叫端。

本堂結論普通參數傳副本；ref 讓方法修改原變數；out 讓方法負責產生並輸出結果。
