ch3_7 Time_程式說明1

這堂把上一堂的時間屬性真的跑起來看。老師用 Console 比較 Time.time 與 Time.realtimeSinceStartup，再用 Time.timeScale 控制 Rigidbody 下落速度，實際做出暫停、快動作與慢動作。

TIME · TIMESCALE · REALTIME

Unity 同時維護「遊戲時間」與「真實時間」

這堂最重要的不是 Console 數字本身，而是看懂：timeScale 可以改變遊戲世界的時間速度，但真實時間仍然持續前進。

01測試程式Time 與 FPS 輸出 02兩條時間軸time / realtime 03timeScale暫停、快慢動作 04deltaTimeUpdate / FixedUpdate 05實際用途暫停 UI、子彈時間
01

測試腳本：把時間值直接印到 Console

老師使用 TestTime，用公開變數控制是否修改 Time.timeScale，並在 Update / FixedUpdate 觀察時間值：

public float timeScale = 0;
public bool changeScale = false;

void Awake()
{
    Application.targetFrameRate = 30;
}

void Update()
{
    if (changeScale)
    {
        Time.timeScale = timeScale;
        changeScale = false;
    }

    Debug.Log("Time:" + Time.time);
    Debug.Log("RealtimeSinceStartup:" + Time.realtimeSinceStartup);
    Debug.Log("Update DeltaTime:" + Time.deltaTime);
}

void FixedUpdate()
{
    Debug.Log("FixedUpdate DeltaTime:" + Time.deltaTime);
}

Application.targetFrameRate = 30 在這堂只是讓測試更容易觀察，重點仍然是 Time 的差異。

02

Time.time 與 realtimeSinceStartup：兩條不同的時間軸

老師先觀察兩個數值。課堂中 realtimeSinceStartup 會比 Time.time 稍早開始累積，因此執行後通常會看到 realtime 略大一些。

Time.time
→ 遊戲時間軸目前走到哪裡
→ 會受到 Time.timeScale 影響

Time.realtimeSinceStartup
→ 遊戲啟動後，現實真正經過多久
→ 不受 Time.timeScale 影響
兩條手錶Time.time 是遊戲世界的手錶；realtimeSinceStartup 是現實世界的手錶。
03

Time.timeScale：直接改變遊戲世界的時間速度

老師在場景中的 Cube 加入 Rigidbody，讓它受到重力往下掉，再利用 Inspector 修改 timeScale：

if (changeScale)
{
    Time.timeScale = timeScale;
    changeScale = false;
}
Time.timeScale = 1f;    // 正常
Time.timeScale = 0.5f;  // 半速
Time.timeScale = 0f;    // 暫停遊戲時間
Time.timeScale = 100f;  // 非常快
Time.timeScale = 0.05f; // 非常慢

當老師把 timeScale 設為 0，Rigidbody 下落會停止；設成 100 時幾乎瞬間掉下去；設成 0.05 時則變成極慢動作。

timeScale不是角色速度倍率，而是整個遊戲「時間流速」的倍率。
04

timeScale = 0 時，遊戲時間停，但 realtime 繼續

這堂最值得看的現象是：當 Time.timeScale = 0，Time.time 不再前進，但 Time.realtimeSinceStartup 仍持續增加。

timeScale = 0

Time.time
→ 停

Time.realtimeSinceStartup
→ 繼續增加

老師因此提醒，如果某個 UI 動畫或效果不希望跟著遊戲暫停，就要使用不受 timeScale 影響的時間概念。

Update 與 FixedUpdate 都印 deltaTime

程式也分別在 Update() 與 FixedUpdate() 印出 Time.deltaTime，是在替下一堂比較 frame 更新與固定物理更新鋪路。

void Update()
{
    Debug.Log(Time.deltaTime);
}

void FixedUpdate()
{
    Debug.Log(Time.deltaTime);
}
先不要超前背細節

這堂先記「Update 跟 frame 走、FixedUpdate 跟固定物理時間走」。兩者的時間差異下一堂再正式整理。

05

實際用途：暫停、慢動作與不受暫停影響的 UI

暫停遊戲
→ Time.timeScale = 0

慢動作 / 子彈時間
→ 0 < Time.timeScale < 1

快動作
→ Time.timeScale > 1

暫停時仍要工作的 UI / 動畫
→ 使用不受 timeScale 影響的時間來源

補充理解：現代 Unity 還有 Time.unscaledDeltaTime、Time.unscaledTime 這類直接處理「不受 timeScale 影響」的 API；這不是老師本堂主要內容，先知道有這種做法即可。

這堂核心遊戲可以暫停自己的時間，但現實時間不會因此停下來。timeScale 正是在控制這兩條時間軸的分離。
