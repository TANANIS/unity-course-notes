ch2_10 類別

這堂開始進入物件導向的基本概念。老師先從人類如何依共同特性分類，帶到 C# 如何把一組相關特性集合成一個 class。

CLASS

把共同特性集合起來，定義一種新的型別

人會用共同特徵區分哺乳類、鳥類等類別；程式裡也可以用相同思路，把某種東西擁有的資料與特性集中在一個類別裡。

01

類別：把共同特性集合在一起

老師先用現實世界的分類說明：人會依照物體或生物的共同特性，把它們分成不同類別。程式設計裡也可以使用相同思路。

當一組資料都在描述同一種東西時，可以把這些特性集中起來，建立一個新的 class。

public class Weapon
{
    // Weapon 相關的特性放在這裡
}
一句話記憶class = 把「這一類東西共同擁有什麼」集中定義起來。
02

課堂範例：Weapon 有哪些特性？

老師用「武器」做例子。建立 Weapon 類別前，先思考武器通常需要描述哪些特性，例如：

攻擊力
描述武器能造成多少傷害。
磨損程度
描述武器目前的損耗狀態。
等級限制
描述使用這把武器需要的等級條件。

以下程式只是在整理老師的概念；字幕沒有完整保留每個欄位的實際名稱與型別，因此欄位型別先當作示意：

public class Weapon
{
    public float attackPower;
    public float wear;
    public int levelLimit;
}
先想「它有什麼」

老師這堂的重點不是欄位名稱本身，而是寫物件導向程式前，先思考這個類別應該包含哪些共同特性，再把它們集中到 class 裡。

03

: 代表繼承

Unity 建立 C# Script 時常會看到：

public class Weapon : MonoBehaviour
{
    void Start()
    {
    }

    void Update()
    {
    }
}

老師這堂要求先把 : MonoBehaviour、Start() 與 Update() 移除，因為目前只是練習建立一般 C# 類別，不需要 Unity 的 Component 行為。

public class Weapon
{
    public float attackPower;
    public float wear;
    public int levelLimit;
}
:
在這裡表示「繼承」。
: MonoBehaviour
表示這個類別繼承 Unity 的 MonoBehaviour。
這堂先刪除
因為目前要觀察最單純的 class，而不是 Unity Component 的生命週期。
04

補充：MonoBehaviour 到底是什麼？

這一節是理解補充，不是老師這段字幕已經完整講授的內容。老師目前只先指出 : 是繼承，並要求這個範例暫時不要繼承 MonoBehaviour。

MonoBehaviour 可以先理解成 Unity 提供給腳本的基底類別。你的 class 繼承它之後，就能以 Unity Component 的方式掛在 GameObject 上，並由 Unity 管理其生命週期。

public class Player : MonoBehaviour
{
    void Start()
    {
        // Unity 在適當時機呼叫
    }

    void Update()
    {
        // Unity 每幀執行
    }
}

相反地，這堂的 Weapon：

public class Weapon
{
}

就是一般 C# 類別，不因為寫在 Unity 專案裡就自動變成可以掛到 GameObject 上的 Component。

直覺版

普通 C# class
    ↓
只是你自己定義的資料與功能

class Player : MonoBehaviour
    ↓
成為 Unity 可以當作 Component 管理的腳本類別
    ↓
可以掛到 GameObject
    ↓
可以參與 Start / Update / Awake 等 Unity 生命週期
不要把兩件事混在一起

class 是 C# 的類別概念；MonoBehaviour 是 Unity 提供的一個特定基底類別。不是「class 一定要繼承 MonoBehaviour」，而是需要成為 Unity Component 腳本時才常會繼承它。

一句話記憶MonoBehaviour = 讓你的 class 接上 Unity GameObject / Component 與生命週期系統的基底類別。
05

直覺記憶：Class 像一張規格書

現在先不要急著把 class 與下一堂的 object 混在一起。這堂只需要把 class 想成：「我先定義這一種東西應該有哪些特性。」

Weapon 規格書
├── 攻擊力
├── 磨損程度
└── 等級限制

下一堂「物件」才會開始處理：有了 Weapon 這種型別之後，怎麼實際建立與使用某一個 Weapon。

本堂結論類別先定義一種東西共同擁有的特性；冒號代表繼承；一般 class 不必繼承 MonoBehaviour。
