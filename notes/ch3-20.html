ch3_20 message_1（物體間的訊息傳遞介紹）

這堂先把 Unity 的 Message 想成「在物件階層裡喊一個方法名稱」。三種方法的核心差別不是喊什麼，而是訊息要留在自己、往子物件傳，還是往父物件傳。

SENDMESSAGE · BROADCASTMESSAGE · SENDMESSAGEUPWARDS

同一句話，可以只喊給自己、往樓下喊，或往樓上喊

課程用「角色中毒後整組模型變綠」當例子：主物件知道自己中毒了，接著用訊息通知階層裡有對應方法的物件一起處理變色。

01Message 是什麼用方法名稱喊話 02SendMessage只在自己身上 03BroadcastMessage自己 + 往下 04SendMessageUpwards自己 + 往上 05三種方向一次記自己 / ↓ / ↑
01

Message：不是搬資料，而是在喊「誰有這個方法就做一下」

課程先假設角色中毒。主角知道自己碰到毒物後，希望自己和下面的模型一起變成綠色。概念可以先畫成：

主角
├─ 身體
└─ 頭
   └─ 帽子

主角：「有 SetGreen() 的，現在執行！」

五歲版：不是爸爸親自跑去把每個小孩塗綠，而是站在家裡喊一句「變綠！」，聽得到而且知道怎麼做的人就自己去做。

一句話記憶Message = 用方法名稱發通知；真正收到誰，取決於你選哪一種 Message。
02

SendMessage：只在自己這個 GameObject 身上喊

SendMessage("SetGreen");

依這堂課的模型，SendMessage 只送給發送者自己，不往父物件或子物件傳。

        爺爺 ✗
          │
        爸爸 ✓  ← SendMessage
          │
        小孩 ✗

五歲版：你關在自己房間裡喊「變綠！」，只有這個房間裡的人聽到，樓上樓下都當沒事。

SendMessage自己喊、自己處理，不往階層上下傳。
03

BroadcastMessage：自己收到，所有子物件也一路收到

BroadcastMessage("SetGreen");

課程用角色模型做示範：如果從上層主物件發送，自己以及下面的子階層都會收到。

        主角 ✓
        /    \
    身體 ✓   頭 ✓
               \
               帽子 ✓

BroadcastMessage
→ 自己 + 往下全部喊

這很適合課程的「中毒變綠」例子：主角收到中毒狀態後，可以往下通知整組角色模型。

BroadcastMessage自己 + 所有子階層。看到 Broadcast 就先想「往下廣播」。
04

SendMessageUpwards：自己收到，再沿著父物件一路往上

SendMessageUpwards("SomeMethod");

這個方向和 BroadcastMessage 相反。如果從下層物件開始發送，訊息會包含自己，再往父階層傳上去。

        爺爺 ✓
          ↑
        爸爸 ✓
          ↑
        小孩 ✓  ← 從這裡發送

SendMessageUpwards
→ 自己 + 往上全部喊

五歲版：小孩在樓下喊「救命！」，自己當然知道自己喊了，爸爸和爺爺也一路聽得到；但自己的小孩不在這條往上的路上。

SendMessageUpwards自己 + 父階層。看到 Upwards 就先想箭頭 ↑。
05

三種 Message 不要背長名字，直接記箭頭

SendMessage
→ 自己

BroadcastMessage
→ 自己 + ↓ 子物件

SendMessageUpwards
→ 自己 + ↑ 父物件

把 Transform hierarchy 想成一棟樓：

          爺爺
            ↑
            ↑ SendMessageUpwards
            ↑
          爸爸
            ↓
            ↓ BroadcastMessage
            ↓
          小孩

SendMessage
→ 原地喊
這堂先到這裡

字幕這堂只介紹三種訊息的傳遞方向，還沒有展開實際程式參數與找不到方法時怎麼處理；那些留到下一堂程式說明再補，不先替課程偷跑。

這堂核心SendMessage = 自己；BroadcastMessage = 自己 + 往下；SendMessageUpwards = 自己 + 往上。
