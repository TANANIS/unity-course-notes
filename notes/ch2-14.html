ch2_14 建構子（constructor）

前面建立 Weapon 物件後，攻擊力、磨損程度與等級限制都要一個一個設定。這堂用建構子把「建立物件」與「設定初始資料」合在一起，讓物件在 new 出來時就帶著需要的初始狀態。

CONSTRUCTOR

物件出生時，順便把初始資料設定好

建構子會在建立物件時執行。它的名稱必須和類別相同，而且沒有回傳型別；也可以接收參數，把多個欄位一次初始化。

01

為什麼需要建構子？

老師先拿前面的 Weapon 當例子。假設一把武器有攻擊力、磨損程度、等級限制三個資料，如果每次建立物件後都要再逐項設定：

Weapon kingSword = new Weapon();

kingSword.AttackPower = 100;
kingSword.Wear = 20;
kingSword.LevelLimit = 90;

每建立一個物件就得重複做一輪。建構子的目的，就是在建立物件的同一刻，把這些初始值一起交進去。

Weapon kingSword = new Weapon(100, 20, 90);
這堂核心建構子 = 建立物件時，自動執行的一段初始化程式。
02

建構子的兩個最重要特徵

字幕明確強調兩件事：

public class Weapon
{
    public Weapon()
    {
    }
}
名稱和類別完全相同
類別叫 Weapon，建構子也必須叫 Weapon。
沒有回傳型別
前面不能寫 void、int、float 等回傳型別。
不要寫成 void Weapon()

如果寫成 public void Weapon()，那就不再是建構子，而是一個剛好和類別同名的普通方法。建構子的「沒有回傳型別」是真的什麼都不寫，不是寫 void。

03

建構子可以接收參數，一次初始化多個欄位

老師接著把攻擊力、磨損程度、等級限制放進建構子的參數中。字幕中的實際變數命名有辨識誤差，以下保留其邏輯：

public class Weapon
{
    private float _attackPower;
    private float _wear;
    private int _levelLimit;

    public Weapon(float attackPower, float wear, int levelLimit)
    {
        _attackPower = attackPower;
        _wear = wear;
        _levelLimit = levelLimit;
    }
}

多個參數和一般方法一樣，用逗號分開。傳進來的值會在建構子裡指定給物件自己的欄位。

傳入 attackPower
        ↓
_attackPower = attackPower;

傳入 wear
        ↓
_wear = wear;

傳入 levelLimit
        ↓
_levelLimit = levelLimit;
初始化不是建立完物件之後再補資料，而是在物件建立的那一刻就把初始資料放進去。
04

new 的括號，就是把資料交給建構子

當建構子定義成：

public Weapon(float attackPower, float wear, int levelLimit)

建立物件時就可以直接傳入三個值：

Weapon kingSword = new Weapon(100, 20, 90);

可以把執行流程想成：

new Weapon(100, 20, 90)
          ↓
找到 Weapon(float, float, int)
          ↓
attackPower = 100
wear        = 20
levelLimit  = 90
          ↓
把值寫進這個新物件的欄位
          ↓
kingSword 建立完成

老師最後用等級限制驗證，傳入 90 後，執行時讀出的等級限制就是 90。

new 與建構子new Weapon(...) 的括號不是裝飾品；裡面的參數會交給對應的建構子。
05

為什麼加了有參數建構子後，原本的 new Weapon() 會報錯？

老師示範：原本程式可以直接寫：

Weapon weapon = new Weapon();

但加入有參數建構子後，原本這種沒有傳參數的寫法出現錯誤，因此又補上一個無參數建構子：

public Weapon()
{
}

public Weapon(float attackPower, float wear, int levelLimit)
{
    _attackPower = attackPower;
    _wear = wear;
    _levelLimit = levelLimit;
}
C# 規則校正

字幕說「所有類別預設會提供一個沒有參數的建構子」，這句要補完整：當你完全沒有自己宣告任何實例建構子時，C# 編譯器才會替類別產生預設的無參數建構子。一旦你自己宣告了 Weapon(float, float, int)，編譯器就不會再自動補 Weapon()；如果兩種建立方式都要保留，就必須自己把兩個建構子都寫出來。

這種同一個類別有多個建構子的寫法，本質上是讓不同的參數組合對應不同的建立方式。

容易踩雷自己寫了任何建構子之後，不要再假設 new 類別() 一定存在。
06

五歲版：建構子就是「出生設定表」

把 class Weapon 想成武器工廠的設計圖，而每次 new Weapon(...) 都是在做一把新的武器。

Weapon 設計圖

public Weapon(float attackPower, float wear, int levelLimit)
{
    ...
}

建構子就像工廠說：

你要造一把新武器？

那出生前先填：

攻擊力：100
磨損：20
等級限制：90

        ↓

new Weapon(100, 20, 90)

        ↓

一出生就是：
_attackPower = 100
_wear = 20
_levelLimit = 90

沒有建構子的初始化思路，常常會變成：

先出生
↓
再改攻擊力
↓
再改磨損
↓
再改等級限制

有建構子後則是：

出生時就把該有的初始資料帶好
五歲版結論建構子 = 物件出生時會自動執行的初始化函式。
和剛才封裝接起來

封裝在控制「外部之後怎麼改我的資料」；建構子則處理「我剛出生時，資料一開始應該是什麼」。兩個概念正好接在一起：先建立合法的初始狀態，再控制之後的修改入口。

07

補充理解：為什麼一定要「出生時」就給值？

這一節是課後補充理解，不是老師字幕原話。先把最重要的一點講清楚：不是所有資料都一定要在建構子裡給，也不是所有物件都必須使用有參數建構子。

如果一個物件允許先建立，再慢慢設定資料，那這種做法完全可以：

Weapon sword = new Weapon();

sword.SetAttackPower(100);
sword.SetWear(20);
sword.SetLevelLimit(90);

真正需要思考的是：在這些設定完成以前，sword 是否已經算是一個可以正常使用的 Weapon？

建構子真正解決的是「必要資料不能被忘記」

假設 Enemy 要正常存在，至少必須有 HP 與攻擊力。如果允許先建立再設定：

Enemy slime = new Enemy();
slime.SetHp(100);
// 忘了設定 Damage

程式可能仍然能執行，但這隻 Enemy 已經處在不完整或不合理的狀態。問題不是「工程師之後不會賦值」，而是這套設計把正確性建立在「希望所有人每次都記得做完所有步驟」上。

如果改成：

Enemy slime = new Enemy(100, 20);

那麼建立 Enemy 的人若漏掉必要資料，建立物件這一步就無法完成，而不是讓一個半成品物件先存在。

核心價值建構子可以把「記得初始化必要資料」變成「建立物件時就必須提供必要資料」。

不是所有值都該塞進建構子

可以先把資料粗分成兩類：

必要的初始資料
沒有它，物件概念上就不完整。例如 Enemy 必須具備的初始生命值與攻擊力、帳號建立時必須有的識別資料。這類資料適合要求在建立物件時就提供。
可以之後才出現的狀態
物件出生後才會變動或新增的資料，例如角色目前的 Buff、是否中毒、武器後續磨損、最後登入時間。這些通常不需要全部塞進建構子。

因此建構子不是為了取代所有賦值，也不是規定「物件所有欄位一出生就必須有自訂值」。它比較像是在回答一個設計問題：

建立這個物件之前，
有哪些條件一定要先成立？

可以用一個簡單問題判斷：

Weapon sword = new Weapon();

什麼都不再設定。
這個 sword 現在能不能被正常使用？

如果答案是「可以，預設狀態本來就合法」，那無參數建構子完全合理。如果答案是「不行，至少必須知道某些資料」，那就可以考慮把那些必要資料放進建構子。

Why，而不只是 How

語法只告訴你 public Weapon(...) 怎麼寫；真正的設計理由是：讓類別自己規定「什麼樣的初始狀態才允許成為一個可用物件」，而不是把正確性全部交給外部程式之後記得補齊。

補充結論建構子不是要求所有資料出生就給，而是可以用來保證「物件成立所必需的資料」在出生時就已經存在。
