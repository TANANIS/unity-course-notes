ch3_1 Unity3D 生命週期介紹

Unity 不會把 MonoBehaviour 當成普通 C# 程式從第一行一路跑到底，而是在物件生命中的特定時機，自動呼叫對應的事件函式。這堂先建立「什麼時候該做什麼事」的時間軸。

MONOBEHAVIOUR · LIFECYCLE

重點不是背函式，而是把程式放到正確的時間點

老師先把遊戲概括成「開始 → 持續運行 → 結束」，再對應到 Unity 腳本的初始化、每幀更新、物理更新，以及停用與銷毀。

01

生命週期：Unity 在不同階段自動呼叫不同函式

老師用遊戲本身來比喻：先開始、在中間持續運作，最後結束。Unity 的腳本也有類似流程，因此我們可以把不同工作放進不同事件函式。

建立 / 啟用
Awake()
   ↓
OnEnable()
   ↓
Start()

持續運行
FixedUpdate()   // 物理時間步
Update()        // 每個畫面的主要邏輯
LateUpdate()    // Update 後的處理

停用 / 結束
OnDisable()
   ↓
OnDestroy()     // 物件真正被銷毀時
生命週期的用途不是 Unity 幫你「排序程式碼」，而是 Unity 在不同時間點主動通知你的腳本：現在該做這類事情了。
02

初始化：Awake → OnEnable → Start

Awake()
物件實例建立後的早期初始化。老師的投影片把它用在初始化變數、取得需要的元件；同一個物件上會早於 Start。
OnEnable()
物件 / Component 進入啟用狀態時呼叫。和 OnDisable 成對看待，因此一個物件生命中可能反覆呼叫多次。
Start()
腳本處於啟用狀態後，在第一次 Update 之前呼叫一次。適合依賴其他初始化已完成後才開始的工作。
void Awake()
{
    // 早期初始化、抓 Component
}

void OnEnable()
{
    // 每次啟用時要做的事
}

void Start()
{
    // 第一次正式開始前的初始化
}
先這樣記Awake = 我出生了；OnEnable = 我上線了；Start = 我要開始工作了。
03

持續運行：FixedUpdate、Update、LateUpdate 各有工作

FixedUpdate()：固定時間步，主要給物理

老師將 Rigidbody 移動等物理相關工作放在 FixedUpdate()。它依照固定的物理時間間隔運作，不是單純「每個畫面跑一次」。

void FixedUpdate()
{
    // Rigidbody、施力等物理處理
}

Update()：每個 frame 的主要遊戲邏輯

Update() 是最常見的每幀更新入口，移動、輸入判斷、一般遊戲邏輯常在這裡處理。不同 frame 之間經過的時間可能不同，因此和速度有關的計算通常會搭配 Time.deltaTime。

void Update()
{
    transform.position += Vector3.forward * speed * Time.deltaTime;
}

LateUpdate()：等 Update 做完，再處理追隨

老師舉的典型例子是攝影機跟隨：先讓角色在 Update() 完成移動，再由攝影機在 LateUpdate() 跟上，避免攝影機拿到角色移動前的位置。

void LateUpdate()
{
    // 例如：攝影機追隨角色
}
三個 UpdateFixedUpdate 看物理時鐘；Update 看畫面更新；LateUpdate 等 Update 做完再收尾。
04

OnDisable 與 OnDestroy 不要混在一起

老師投影片在 OnEnable 說明中提到它會和 OnDisable() 一起使用；課堂流程最後則介紹 OnDestroy()。這兩個代表的事情不同。

gameObject.SetActive(false);
// → 停用，不代表物件已被銷毀
// → OnDisable()

Destroy(gameObject);
// → 物件進入銷毀流程
// → OnDestroy()
OnDisable()
物件或腳本從啟用狀態離開時呼叫，之後仍可能再次 OnEnable。
OnDestroy()
物件被真正銷毀時，用來做最後的清理工作。
差別Disable 是「先下線」；Destroy 才是「這個物件要沒了」。
05

新版 Unity 校正：核心沒變，但流程圖不能背成死循環

這堂的核心生命週期在目前 Unity 版本仍然成立。官方現在仍描述同一物件的初始化順序為 Awake → OnEnable → Start，而 LateUpdate 仍在該幀的 Update 之後。

最重要的校正

不要把 FixedUpdate → Update → LateUpdate 理解成每一幀固定各跑一次。 FixedUpdate 跟物理的 Fixed Timestep 走，Update 跟渲染 frame 走；兩個時鐘不是一對一。

// 例如固定物理時間為 0.02 秒：大約 50 次 / 秒
// 如果畫面是 100 FPS：Update 約 100 次 / 秒，FixedUpdate 約 50 次 / 秒
// 如果畫面只有 25 FPS：一個渲染 frame 間可能需要補跑多次 FixedUpdate

另外，只能安全依賴「同一個物件」上的 Awake 早於 OnEnable。不同 GameObject 之間的 Awake / OnEnable 誰先誰後，不應拿來當程式依賴。

參考：Unity Manual：事件函式執行順序

06

真正要背的是「工作類型」，不是一串函式名

初始化？
→ Awake / Start

每次啟用或停用？
→ OnEnable / OnDisable

物理？
→ FixedUpdate

每幀主要邏輯？
→ Update

必須等 Update 做完？
→ LateUpdate

最後清理？
→ OnDestroy

之後看到一段程式，不要先問「老師把它寫在哪個函式」。先問：這件事應該在物件生命中的哪個時間點發生？

一句話記憶Unity 生命週期就是把「何時執行」變成一組明確的事件函式。
