ch3_24 Invoke_簡介

這堂先介紹 Unity 的 Invoke 系列用途：如果某個方法不想現在立刻執行，而是希望延遲幾秒、固定間隔重複呼叫，或之後取消這些排程，就可以使用 Invoke、InvokeRepeating 與 CancelInvoke。

INVOKE · DELAY · REPEAT · CANCEL

不是現在做，而是叫 Unity 幫你「晚點再做」

ELI5：把 Invoke 想成 Unity 裡的鬧鐘。你先告訴 Unity「幾秒後幫我呼叫這個方法」，Unity 會把它排進時間表，等時間到了再替你執行。

01為什麼需要 Invoke延遲與倒數 02Invoke一次性鬧鐘 03InvokeRepeating循環鬧鐘 04CancelInvoke取消排程 05同類別限制方法要在同一個 class 06整堂模型排程 → 等待 → 呼叫
01

這堂先從兩種需求開始：倒數計時、延遲執行

課程先提出兩個常見需求：一個是做倒數計時，另一個是讓某個方法不要現在執行，而是延遲一秒、兩秒或其他時間之後再呼叫。

現在
 ↓
我有一個方法要執行
 ↓
但不是現在
 ↓
希望過幾秒再執行

Invoke 系列就是 Unity 提供的一種簡單排程方式。

問題核心Invoke 解決的是「晚一點再呼叫方法」以及「固定時間重複呼叫方法」這類需求。
02

Invoke：延遲之後，只呼叫一次

課程介紹的第一種形式是 Invoke。第一個資訊是方法名稱字串，第二個資訊是要延遲多久。

Invoke("方法名稱", delay);

ELI5：它就是一次性鬧鐘。

現在
 ↓
Invoke("Explode", 2f)
 ↓
Unity 設一個 2 秒鬧鐘
 ↓
2 秒到了
 ↓
呼叫 Explode()

這堂只先講基本概念，實際程式碼會留到下一堂再看。

Invoke等指定時間後，呼叫指定方法一次。
03

InvokeRepeating：第一次先等，之後固定間隔一直呼叫

第二種是 InvokeRepeating。課程說明它需要方法名稱、第一次呼叫前要延遲多久，以及之後每次重複呼叫的時間間隔。

InvokeRepeating(
    "方法名稱",
    第一次延遲多久,
    之後每隔多久
);

ELI5：這不是一次性鬧鐘，而是循環鬧鐘。

開始
 ↓
先等 2 秒
 ↓
呼叫一次
 ↓
再等 1 秒
 ↓
再呼叫一次
 ↓
再等 1 秒
 ↓
繼續重複...

課程也用倒數計時當作容易聯想到的用途：如果希望每一秒重複做一次事情，就可以用這種重複呼叫的概念。

InvokeRepeating先等第一次延遲，之後按照固定間隔重複呼叫同一個方法。
04

CancelInvoke：不想等了，或不想再重複，就把排程取消

第三個是 CancelInvoke。如果原本排好的延遲呼叫突然不需要了，或某個 InvokeRepeating 不想再繼續呼叫，就可以指定方法名稱把它取消。

CancelInvoke("方法名稱");

ELI5：

Invoke          = 設一次性鬧鐘
InvokeRepeating = 設循環鬧鐘
CancelInvoke    = 把那顆鬧鐘關掉
CancelInvoke取消指定方法目前排定的延遲或重複呼叫。
05

這堂特別提醒：Invoke 用方法名稱找同一個類別裡的方法

課程提醒，這種 Invoke 寫法指定的方法名稱必須是在同一個類別裡。也就是說，某個 class 裡呼叫 Invoke 時，指定的方法也要存在於這個 class 中；不能只靠方法名稱字串直接去其他類別裡找。

class Bomb
{
    Invoke("Explode", 2f);

    void Explode()
    {
        // 同一個 class 裡的方法
    }
}
這堂限制Invoke 指定的方法名稱，要對應同一個類別中的方法。
06

把整堂壓成三顆鬧鐘

Invoke
＝ 延遲後執行一次
＝ 一次性鬧鐘

InvokeRepeating
＝ 延遲開始 + 固定間隔重複
＝ 循環鬧鐘

CancelInvoke
＝ 取消排定的呼叫
＝ 關掉鬧鐘

真正要記住的思考方式是：

我不是現在呼叫方法
        ↓
我先告訴 Unity
「過幾秒再幫我呼叫」
        ↓
Unity 幫我排程
        ↓
時間到了
        ↓
方法被呼叫
這堂核心Invoke 系列就是把方法呼叫交給 Unity 排程：晚點做、重複做，或取消不要做。
