ch3_8 Time_程式說明2

這堂把 Time.deltaTime 和 FPS 正式接起來，並比較 Update() 與 FixedUpdate() 的時間特性。重點不是背 0.033 或 0.02，而是理解「每幀執行」怎麼換算成「每秒多少」。

FPS · DELTATIME · FIXEDUPDATE

FPS 告訴你一秒幾幀，deltaTime 告訴你這一幀花幾秒

FPS 越高，每一幀能分到的時間越短；FPS 越低，每一幀經過的時間越長。Time.deltaTime 就是把每幀程式換算成每秒速度的關鍵。

01FPS 與 deltaTime互為時間尺度 0230 FPS 測試targetFrameRate + VSync 03Update每幀時間會波動 04FixedUpdate固定時間步長 05速度 × deltaTime每秒轉成本幀
01

FPS 與 deltaTime：一秒幾幀 vs. 一幀幾秒

老師先只輸出 Update() 裡的 Time.deltaTime，可以看到數值會上下波動；同時觀察 FPS，也會發現 FPS 本身並不是完全固定。

FPS
= 每秒跑幾個 Frame

deltaTime
= 上一幀到這一幀經過幾秒

理想情況下可以用下面的關係建立直覺：

30 FPS  → 1 / 30  ≈ 0.0333 秒 / 幀
60 FPS  → 1 / 60  ≈ 0.0167 秒 / 幀
120 FPS → 1 / 120 ≈ 0.0083 秒 / 幀
方向關係FPS 越高 → deltaTime 越小；FPS 越低 → deltaTime 越大。
02

老師的 30 FPS 測試設定：先關 VSync，再設 targetFrameRate

為了讓 deltaTime 比較容易觀察，老師把目標 FPS 設為 30：

void Awake()
{
    Application.targetFrameRate = 30;
}

講義另外要求先到 Quality 設定把 VSync 關掉：

Edit
→ Project Settings
→ Quality
→ Other
→ VSync Count
→ Don't Sync

這樣測試時 FPS 才會比較接近程式指定的 30，Time.deltaTime 也比較容易看到約 0.033 的結果。

教學測試，不是硬保證

Application.targetFrameRate = 30 是設定目標幀率，不代表每一幀都會精確等於 1/30 秒。實際 FPS 還是可能有些波動。

03

Update：跟著畫面 Frame 跑，所以 deltaTime 會波動

即使目標 FPS 設成 30，實際每一幀仍可能略快或略慢，因此 Update 裡的 deltaTime 不會像數學題一樣永遠固定。

void Update()
{
    Debug.Log("Update DeltaTime:" + Time.deltaTime);
}
可能看到：
0.031
0.034
0.033
0.036
...

所以 Update() 的心智模型是：每個畫面更新一次，但每兩幀之間實際經過多久並不保證完全相同。

UpdateFrame-based：每幀執行，但每幀時間可能不同。
04

FixedUpdate：固定時間步長，通常用於物理

老師接著只觀察 FixedUpdate() 裡的時間，會看到數值相對固定。課程測試看到的重點是約 0.02 秒。

void FixedUpdate()
{
    Debug.Log("FixedUpdate DeltaTime:" + Time.deltaTime);
}
Update：
0.031
0.034
0.033
...

FixedUpdate：
0.02
0.02
0.02
...

因此可以接回前面的生命週期：

Update
→ 跟畫面 frame 走
→ 時間間隔會波動

FixedUpdate
→ 跟固定物理時間步走
→ 時間間隔固定
FixedUpdate不是「每一幀固定一次」，而是按照固定的物理時間節奏更新。
05

speed × deltaTime：把「每秒多少」換成本幀該做多少

這堂真正會一路用下去的公式不是 FPS，而是：

本幀距離 = 每秒速度 × Time.deltaTime

例如想讓物件每秒往前 20 個單位：

transform.position +=
    Vector3.forward * 20f * Time.deltaTime;

30 FPS 時，每幀約走：

20 × 0.0333 ≈ 0.666

60 FPS 時，每幀約走：

20 × 0.0167 ≈ 0.333

雖然每幀走的距離不同，但一秒累積起來都大約是 20。這就是 deltaTime 的核心用途。

最重要的錯誤對照

position += 20; 是「每幀加 20」；position += 20 * Time.deltaTime; 才是「每秒加 20」。不要讓玩家因為買了高刷新率螢幕就順便得到移速外掛。

這堂核心deltaTime 是「每秒」與「每幀」之間的換算器。
