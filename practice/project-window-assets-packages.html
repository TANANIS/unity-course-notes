Project 視窗：Assets 與 Packages

建立 Universal 3D 空白專案後，先辨認 Project 視窗裡哪些是自己的專案內容、哪些是 Unity 或套件提供的功能，避免把所有資料夾當成同一類東西。

PROJECT WINDOW

先建立最重要的二分法

Assets 是專案內容；Packages 是專案依賴的套件。 平常開發主要會在 Assets 中建立與整理自己的場景、腳本、Prefab、材質與美術資產。

01

Assets：自己的專案內容

Assets 是 Unity 專案中最常直接工作的區域。放進這裡的場景、腳本、Prefab、材質、圖片、模型、音效等，會被 Unity 匯入並成為 Project 中可使用的資產。

核心記憶Assets = 我正在做的遊戲內容。
Scenes
存放場景檔（.unity）。目前的測試場景或正式關卡都會放在這裡。
Scripts
存放自己的 C# Script。Universal 3D 預設不一定會建立，通常由自己新增。
Prefabs
存放可重複使用的 GameObject 樣板。
Materials
存放材質資產，控制物件表面如何被渲染。
Art
可用來集中模型、貼圖、Sprite 等美術內容；是否再細分視專案規模而定。
02

Packages：專案依賴的功能套件

Packages 顯示目前專案正在使用的 Unity Package。它們不是一般遊戲素材，而是替專案提供額外 API、Editor 工具或系統功能。

核心記憶Packages = 這個專案依賴哪些工具與功能。
AI Navigation
NavMesh 與 AI 導航相關功能。
Input System
Unity 新版輸入系統，處理鍵盤、滑鼠、手把與其他輸入裝置。
Burst
將特定 C# 工作最佳化編譯，常與 Jobs / DOTS 生態一起使用。
Collections
提供高效能容器與資料結構，常見於 Jobs / DOTS 工作流程。
Mathematics
Unity 的數學型別與函式套件，例如 float3 等。
JetBrains Rider Editor
Unity 與 Rider IDE 的整合支援。
Newtonsoft Json
常用的 JSON 序列化與反序列化工具。
管理 Package

新增、移除或檢查套件時，優先使用 Window → Package Manager，而不是直接進入 Packages 內容中亂改原始檔。

03

Universal 3D 模板中的預設內容

使用 Universal 3D 建立專案時，Unity 會替專案配置 URP，因此除了 Scenes 之外，通常還會看到一些由模板建立的設定與教學內容。

Settings
通常包含 URP Renderer、Render Pipeline Asset 等渲染設定。這些不是垃圾檔，剛開始不要隨意刪除。
TutorialInfo
模板或 Welcome / 教學功能使用的內容，可能包含 Icons 與 Scripts。通常不是遊戲核心的一部分。

是否刪除模板附帶內容，不需要在剛開專案時急著處理。先確認用途與引用關係，再決定是否清理。

04

小型練習專案先用簡單目錄

剛開始不需要先設計一套巨大企業級目錄。只要讓內容有基本分區，就足夠支撐目前的驗收練習。

Assets
├─ Scenes
├─ Scripts
├─ Prefabs
├─ Materials
└─ Art

目錄結構應該隨專案需求成長。若現在根本還沒有動畫、音效、Shader，就沒有必要先建立二十個空資料夾假裝專案很成熟。

05

目前階段的操作原則

  1. 01
    自己的內容放 Assets

    場景、腳本、Prefab、材質、美術資產都以 Assets 為主要工作區。

  2. 02
    Packages 當作依賴理解

    知道它們提供什麼功能即可，不需要把每個 Package 內容讀完。

  3. 03
    透過 Package Manager 管理套件

    新增或移除功能時使用 Unity 正式提供的管理介面。

  4. 04
    不要為整理而整理

    先讓 Project 可以被理解、可以繼續開發，再視需求擴充目錄結構。
