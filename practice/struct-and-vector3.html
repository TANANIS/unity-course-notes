struct × Vector3：從值型別理解 Unity 向量

這篇不是 ch2_15 字幕重寫，而是從「struct 到底為什麼存在？」一路追問到 Unity 的 Vector 設計。目標不是背 API，而是把 struct、class、Vector3、Transform 與移動之間的關係串起來。

FROM STRUCT TO VECTOR

Vector3 沒有魔法，它只是一包有規則的數字

struct 比較像「一份值」；class 比較像「一個有身分、大家可能共同指向的東西」。Vector3 很適合 struct，因為我們通常關心的是 (x, y, z) 這組值是多少，而不是「這是哪一隻 Vector3」。

01

五歲版：struct 是影印一份，class 是拿到同一個地址

先把正式名詞放旁邊。最直覺的差異可以想成：

struct
= 一張資料紙
= 給別人時，通常是影印一份內容

class
= 一個真正存在的東西
= 給別人時，通常只是再抄一份它的地址

struct：各自有自己的那份值

Vector3 a = new Vector3(1, 2, 3);
Vector3 b = a;

b.x = 999;

// a 仍然是 (1, 2, 3)
// b 變成   (999, 2, 3)

class：兩個變數可能在操作同一個物件

Weapon a = new Weapon();
Weapon b = a;

// a 與 b 都參考同一個 Weapon
// b 修改那個 Weapon，a 再去看時也會看到修改後的結果
先這樣記struct = 複製內容；class = 複製怎麼找到同一個物件的參考。
02

為什麼 Vector 很適合是 struct？

因為 Vector 通常是在表達「一個值」。例如位置 (1, 2, 3)，我們關心的是這三個數字本身，而不是這組數字有沒有一個獨一無二的身分。

Player
→ 常會問：這是哪一個 Player？
→ 有身分概念

Vector3(1, 2, 3)
→ 常會問：這組位置 / 方向是多少？
→ 值本身比較重要

所以複製 Vector3 時，最自然的直覺通常是「把現在這組值記一份下來」，而不是讓兩個變數永遠綁著同一個 Vector 物件。

設計直覺class 比較像「哪一個東西」；struct 比較像「這個值是多少」。
03

Vector2 / Vector3 / Vector4 的數字不是版本號

數字代表這個向量有幾個分量：

Vector2
(x, y)，兩個分量。常用於 2D 座標或只需要兩個數值的情境。
Vector3
(x, y, z)，三個分量。3D 世界的位置、方向、位移非常常用。
Vector4
(x, y, z, w)，四個分量。某些圖形、Shader 或需要四個數值的資料會使用。

一般不需要特地做一個常用的 Vector1，因為只有一個數值時直接用 float 通常就夠了。

04

Vector3 的核心，其實真的只是三個數值

如果只留下最核心概念，可以自己寫出一個迷你版本：

public struct MyVector3
{
    public float x;
    public float y;
    public float z;

    public MyVector3(float x, float y, float z)
    {
        this.x = x;
        this.y = y;
        this.z = z;
    }
}

Unity 的 Vector3 當然比這個完整很多。真正方便的地方不只是把三個 float 綁成一包，而是還提供大量向量運算與常用值，而且 Unity 自己的 API 也都認得 UnityEngine.Vector3 這個型別。

自己的 MyVector3
= x + y + z

Unity Vector3
= x + y + z
+ 常用方向
+ 向量運算
+ 距離 / 長度 / 正規化等工具
+ Unity API 共同使用的標準型別
長得一樣，不代表是同一型別

即使 MyVector3 也有 x、y、z，它仍然不是 UnityEngine.Vector3。所以不能因為內容長得一樣，就直接塞給要求 Vector3 的 Unity API。

05

Vector3 自己不會移動任何東西

這是這次對話裡最重要的一個拆解：Vector3 只是資料，它可以描述位置、方向或位移；真正改變物件的是 Transform、Rigidbody 等系統。

Vector3 move = new Vector3(1, 0, 0);

// 到這裡只建立了一組資料
// 物件還沒有移動

當你把這組資料交給 Transform：

transform.Translate(move);

才變成：

Vector3
= 「往 X 方向 1」的指令紙條

Transform.Translate(...)
= 讀這張紙，真的去改物件的位置

直接設定位置也是同一件事：

transform.position = new Vector3(10, 5, 0);

不是 Vector3 自己把東西搬走，而是你把 Transform 的位置資料設定成 (10, 5, 0)。

一句話Vector3 負責描述「去哪裡 / 往哪裡 / 移多少」；Transform 等系統負責真的做事。
06

目前階段最值得認得的 Vector3 工具

不用背完整 API。先認得下面這些，已經足夠支撐大量初階移動與位置計算。

x / y / z
三個分量。
Vector3.zero
(0, 0, 0)。
Vector3.up / right / forward
常用的上、右、前方向。
magnitude
這個向量有多長。
normalized
保留方向，把長度變成 1，方便把「方向」與「速度」分開。
Vector3.Distance(a, b)
取得兩個位置之間的距離。
Vector3.MoveTowards(...)
從目前位置往目標位置靠近一段距離。
Vector3.Lerp(...)
取得兩個向量之間某個比例的位置。
+ - * /
Unity 已經替 Vector3 定義常用運算，例如位置相減取得位移方向、方向乘速度。

非常值得看懂的一行

Vector3 direction =

07

把理解變成自己的測試

  1. 01
    自己寫 MyVector3

    做一個只有 x、y、z 與建構子的 struct。建立 a，再寫 MyVector3 b = a;，修改 b.x，確認 a 不會跟著改。

  2. 02
    和 class 做同一個實驗

    寫一個簡單 class，建立 a，再讓 b = a；透過 b 修改欄位，確認 a 看到的是同一個物件被修改後的狀態。

  3. 03
    讓 Vector3 真正參與 Unity

    先建立 Vector3 move = Vector3.right;，確認單純建立 move 不會動；再交給 transform.Translate(move)，觀察真正執行移動的是誰。

  4. 04
    自己算「往目標的方向」

    建立兩個 GameObject，使用 (target.position - transform.position).normalized 取得方向，再用 Debug.Log 或移動測試確認結果。

這篇真正想留下的東西Vector3 不是 Unity 的移動魔法；它是一個很適合用 struct 表達的「三維值」，而 Unity 的各種系統拿這個共同型別來交換位置、方向與位移資料。
