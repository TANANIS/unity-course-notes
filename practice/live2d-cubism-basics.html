Live2D Cubism 基礎動態實作

這次的目標不是製作完整 VTuber 模型，而是把既有插圖拆成可變形部件，先用 Live2D Cubism 做出適合 Wallpaper Engine 的輕微動態效果。

PSD → DEFORMER → PARAMETER

先讓一個部件真的動起來，再擴張模型

這次實作刻意縮小範圍，先從頭髮開始。重點是理解 Cubism 中素材、變形器、參數與 Keyform 的關係，而不是一次把所有功能都塞進模型。

01

這次練習要做到什麼？

原始需求是把一張插圖做成 Wallpaper Engine 可使用的 Live2D 輕微動態，因此不追求完整臉部捕捉或 VTuber Rig。

目標先拆出可獨立變形的部件 → 在 Cubism 裡建立基本結構 → 先讓頭髮自然擺動。

當時曾整理或測試的素材包含頭髮、身體／皮膚、眼睛、嘴巴、手、衣服、腿、椅子等部件；實際練習時則先把範圍縮到頭髮。

02

素材準備：拆圖不是只把可見部分切開

Live2D 會讓原本靜止的部件移動，所以被遮住的區域可能突然露出來。拆圖時需要預先考慮「移動後會看到什麼」。

頭髮
獨立成可以變形的素材，方便建立擺動。
臉／皮膚
如果原本被頭髮遮住，仍應把可能露出的後腦、皮膚或輪廓補完整。
其他可動部件
手、衣服、眼睛、嘴巴等可依之後需要逐步拆分，不必第一次就全部完成。
實作策略

第一次不要追求「整張圖全部 Live2D 化」。先選一個最明顯、最容易驗證的部件，例如頭髮，確認流程真的走通。

03

Cubism 中這幾個東西怎麼串起來？

基本流程PSD 圖層 → ArtMesh → Warp Deformer → Parameter → Keyform
ArtMesh
匯入 Cubism 後真正承載圖像並可被變形的網格。
Warp Deformer
用一個變形器包住部件，透過拉動 Deformer 來帶動底下的 ArtMesh，比直接亂拉 Mesh 更容易管理。
Parameter
控制變化的軸。例如這次建立「髮擺動 X」。
Keyform
記錄某個 Parameter 值下，物件應該變形成什麼樣子。
04

第一次實作：頭髮擺動

這次先建立一個「髮擺動 X」參數，使用三個基本 Keyform：

-1    0    +1
-1
頭髮往左偏移的狀態。
0
原始中立狀態。
+1
頭髮往右偏移的狀態。

實作時主要選取的是頭髮所屬的 Warp Deformer，在各個 Keyform 上調整變形，而不是把參數本身當成可以拖動的圖像。

自然感髮根少動、中段適量、髮尾最多。

因為目標是桌布的輕微動態，所以幅度不需要很大。頭髮只要有柔和的偏移，就已經能讓靜態插圖產生活感。

05

頭髮移動後露出透明洞怎麼辦？

實作時遇到的問題是：頭髮原本遮住的區域沒有內容，一旦把頭髮往旁邊拉，就會看到透明缺口。

正式處理方式不是在 Cubism 裡「補色」，而是回到原始 PSD，在 Photoshop、CSP、Krita 等繪圖軟體把底下可能露出的素材補完整。

  1. 01
    確認是哪個區域露洞

    例如後腦、皮膚、脖子或背景。

  2. 02
    回原始 PSD 補內容

    把原本被遮住、但變形後會看到的部分補出來。

  3. 03
    重新更新 Cubism 素材

    讓修正後的圖層重新進入目前模型。

臨時權宜方法

也可以先減少變形幅度或增加素材重疊來避免露洞，但這只是限制症狀；如果真的需要那個動作範圍，還是應該把底圖補完整。

06

修改 PSD 後，Cubism 不是即時同步

當時特別確認過：修改原始 PSD 並不代表 Cubism 畫面會在同一瞬間自動跟著改。

修改 PSD
→ 儲存 PSD
→ 回到 Cubism
→ 更新／重新載入來源 PSD
→ 確認部件是否正確更新

實際操作時可先注意 Cubism 是否出現素材更新提示；若沒有，就需要手動執行重新載入或更新來源素材。必要時重新開啟專案再確認。

07

這次刻意先不做的內容

第一次練習時先把範圍壓小，以下項目並不是不重要，而是當時決定等基本頭髮變形跑通後再處理：

  • Physics 物理演算
  • 呼吸
  • 眼睛與眨眼
  • Angle X / Angle Y
  • Texture Atlas
  • moc3 匯出
  • Wallpaper Engine 最終匯入
